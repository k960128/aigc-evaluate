# 大模型安全智能体 (Security Copilot) 整体设计方案

## 🎯 系统定位与架构概览

本系统定位于“辅助型安全智能体 (Assistive Security Agent)”，面向企业内部的安全策略工程师与业务研发人员。它不再盲目追求自主攻击，而是充当两项核心角色：

1. **安全诊断 X 光机**：将黑盒的拦截逻辑白盒化，提供单点透视与沙箱调参能力。
2. **合规知识大字典**：挂载外部记忆（RAG）与数据库工具（Tool Calling），解答边界争议并辅助策略制定。

---

## 🛠️ 核心模块一：安全评测助手 (Diagnostic Workbench)

**交互形态**：左右分栏的工作台（Workbench）。左侧为靶场输入与参数配置，右侧为三层漏斗动态诊断瀑布流。

### 1. 单点靶向全链路诊断 (Full-Link Traceability)

这是整个助手的核心，用于解答业务方“为什么这句话被拦了”的客诉。系统会模拟线上真实网关，让被测文本依次穿透三层防线并可视化展示：

* **L1 层诊断**：高亮展示文本中命中的具体违规词（如 `局域网嗅探`），标注耗时（微秒级）及对应的 `risk_details_id`。
* **L2 层诊断**：展示 Milvus 和 ES 召回的 Top 3 相似样本（正向锚点与负向锚点），并提供余弦相似度绝对得分与当前阈值的对比图。
* **L3 层诊断**：以可折叠面板的形式，展示裁判大模型的完整思维链（CoT），包括意图识别、红线比对和最终打分理由。

### 2. 沙箱参数局部调优 (Interactive Sandbox Tuning)

提供“所见即所得”的策略调试环境，供工程师在线寻找最佳阈值。

* **滑动调参**：提供 L2 向量拦截阈值的滑动条（如 `0.85` 调至 `0.90`）。
* **类目隔离**：允许用户限定扫描范围，例如只用“1029恶意代码”的规则库去扫当前文本，屏蔽其他 30 个小类的干扰。
* **模型热切**：在 L3 诊断中，允许临时切换底层的裁判大模型（如从 `Qwen-Max` 切换为 `GPT-4o`），对比不同基座模型的价值观判断差异。

### 3. 命中规则溯源与一键启停 (Rule Origin & Hot-Swapping)

实现从“发现误杀”到“线上止血”的极速闭环。

* 当系统在 L1 或 L2 层提示拦截时，诊断卡片会精确显示该规则的来源（如：来源于 V_20260401 版本的 1014 类目）。
* 提供一个“高危操作”按钮：**【停用该特征】**。权限校验通过后，直接修改 MySQL 中该特征的 `sync_status`，并秒级热更至线上的 AC 自动机或 Redis 缓存中。

### 4. 向量边界“白箱”对比分析 (Vector Boundary Analysis)

解决深度学习模型“不可解释性”的痛点。

* 当某句话被 L2 Milvus 拦截时，工作台同时展示该句话距离知识库中“最危险的黑样本”**和**“最安全的白样本”的相对距离。
* 辅助安全工程师直观判断：到底是需要降低拦截阈值，还是需要在知识库中补充更多的“安全拒绝（白样本）”来增强向量空间的竞争拉扯。

## 🧠 核心模块二：知识库问答 Copilot (Knowledge Base Q&A)

**交互形态**：类似 ChatGPT 的纯对话窗口，支持流式输出、引用来源折叠和 Markdown 富文本渲染。

### 1. 基于 31 小类的语义界定问答 (Semantic Compliance RAG)

将厚重的合规文档转化为可以随时提问的安全专家。

* **实现机制**：将公司内部的安全红头文件、31 小类风险定义细则、历史定性争议会议记录进行切片，存入现有的 ES 和 Milvus 作为外挂知识库。
* **业务场景**：运营提问：“大模型在小说里描写车祸，符合 1015 类目拦截标准吗？” 智能体去 Milvus 检索规则切片，并回答：“根据《安全规范 V2.0》，不涉及故意诱导的文学描写属于安全边界，建议放行。”并附带原始文档的 Reference 链接。

### 2. 资产大盘与特征词自然语言查询 (Text2SQL Data Query)

赋予智能体调用数据库工具（Function Calling）的能力，替代繁琐的表单查询。

* **实现机制**：配置一个只读权限的 MySQL 数据源，授予大模型 Text2SQL 的工具权限。
* **业务场景**：安全主管提问：“目前归属在毒品类（1007）下的 L1 熔断特征词共有多少个？” 智能体自动生成 `SELECT COUNT(*) FROM risk_vocabulary_keyword WHERE...`，并在聊天窗口直接返回汇总数字和前 5 条最新数据。

### 3. 历史相似 Bad Case 检索辅助 (Similar Precedent Retrieval)

在处理模棱两可的灰色客诉时，用来“寻找判例”。

* **实现机制**：对接“历史评测失败明细表”的 Milvus 分区。
* **业务场景**：工程师输入一段奇怪的越狱 Prompt。智能体自动提取向量，去历史库中捞出过去 6 个月内长得最相似的 3 个历史判例，并告知当时人工或系统的最终定性（PASS 或 FAIL），确保判罚尺度的一致性。

### 4. Zero-Day 漏洞特征一键提取入库 (Feature Extraction & Ingestion)

将外部情报迅速转化为内部防御资产。

* **实现机制**：利用大模型强大的 NER（命名实体识别）和摘要能力。
* **业务场景**：运营人员在社区看到一段新的绕过 Prompt，直接粘贴给助手。助手自动提炼出该 Prompt 中的核心毒素特征（如新出现的黑客暗语），并在对话流中生成一个 JSON 卡片。用户点击【确认采用】，系统自动将该特征封装入库，进入防线生效队列。

## 💻 技术落地架构 (Java 21 / Spring Boot 栈)

1. **编排引擎**：放弃厚重的外部框架，直接使用 Spring Boot 结合 Java 21 的 `StructuredTaskScope` 来编排 L1、L2、L3 的并行/串行调用逻辑，代码极其轻量且性能极高。
2. **状态管理**：前端使用 Ant Design Vue 维护工作台的双向绑定状态，后端完全无状态化（Stateless），通过 RESTful API 返回带步骤树（Step Tree）的 JSON 数据。
3. **混合检索 (Hybrid Search)**：在 RAG 问答模块，充分利用现有的双路召回：ES 保障专业术语（如 `CVE-2026-XXX`）的精确命中，Milvus 保障长文本对话的语义相似度命中，最后通过 RRF（倒数排序融合）算法进行重排。
