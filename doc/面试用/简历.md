# 项目经历
## 大模型安全评测平台
### 项目介绍
针对大模型在敏感场景下的输出风险，设计并实现自动化安全评测平台，支持对不同大模型进行批量安全能力评估，并通过智能评测助手提供链路诊断、规则溯源、误杀漏判分析和风险资产查询能力，为企业模型上线前安全准入提供支撑。

### 技术栈
SpringBoot / SpringCloud Alibaba / Spring AI / MySQL / MyBatis-Plus / Nacos / Redis / RocketMQ / Sharding-JDBC / Elasticsearch/ Milvus / RAG/ Text2SQL

### 项目说明
**平台侧：**

1. 基于策略模式、工厂模式抽象统一模型调用层，封装 OpenAI、DeepSeek、TELE、通义千问等多厂商模型接入能力，结合页面化配置支持模型厂商、密钥、调用参数的动态切换。
2. 针对模型 API 并发限制，基于 Redisson 分布式信号量实现模型维度并发控制，许可数量由模型配置控制；未获取许可时交由 MQ 重试，避免高并发下重复压测下游模型接口。
3. 参与设计并实现大模型安全评测异步流水线，将模型调用与安全评测拆分为独立 RocketMQ 处理链路，降低长耗时模型调用对主流程的阻塞影响。
4. 构建 L1/L2/L3 三层安全判定链路：L1 基于 AC 自动机进行风险词快速拦截，L2 基于 Elasticsearch 与 Milvus 召回风险特征并通过 RRF、Rerank 和阈值路由输出判定，L3 基于 LLM-as-Judge 模型对模糊样本进行语义级裁判。
5. 设计评测过程节点日志机制，记录 MODEL_CALL、L1、L2、L3 各阶段输入快照、输出快照、结构化结果、节点耗时和异常信息，为误杀漏判分析、人工复核和异常排查提供可追溯依据。
6. 面对海量样本评测结果和链路日志，基于 Sharding-JDBC 实施核心业务表的 **分库分表** 策略以突破写入瓶颈。评测详情与节点日志基于同一评测详情 ID 规划分片，保证单题诊断链路局部查询效率；ES 承担任务维度筛选、风险统计和规则命中聚合查询。
7. 设计 MySQL 到 Elasticsearch 的评测结果投影同步链路，通过 outbox 事件表记录结果明细和节点日志变更，再由 RocketMQ 消费者回查 MySQL 最新数据写入 ES；保证查询侧数据最终一致。

**评测助手侧：**

1. 设计并实现安全评测助手 ，围绕评测链路诊断、规则特征溯源、误杀漏判分析、合规知识问答、历史案例检索、风险资产查询、特征提取和报告辅助等场景抽象意图体系。
2. 设计并实现多源智能路由检索架构：基于 LLM 语义分析实现查询路由，自动将用户问题路由至 Elasticsearch（向量/全文混合检索，大模型安全相关问题咨询）、MySQL（Text2SQL 结构化查询，风险资产等），路由失败时返回可解释的降级响应。
3. 实现后端 Slot Validator 槽位校验机制，将大模型负责语义理解，后端负责必填槽位、业务边界和执行条件校验，避免直接信任模型输出导致错误路由。
4. 基于 conversationId 实现多轮补槽状态管理，当用户缺少任务描述、结果明细、风险小类、时间范围等关键信息时保存 pending 状态；下一轮用户补充信息时沿用原意图补槽，避免被重新识别成无关问题。
5. 实现 Text2SQL 风险资产查询原型，支持基于自然语言查询风险小类、风险词、同步状态等结构化数据，并增加只读 SQL 校验、表白名单、多语句拦截和默认 LIMIT 限制，降低越权查询和误执行风险。

## 锅美优食
### 项目介绍
国美电器旗下社区食材零售平台，覆盖订单、商品、库存、价格等核心业务，支撑高并发交易与复杂业务场景。

### 技术栈
Spring Boot / Spring Cloud Alibaba / MyBatis / MySQL / Redis / RocketMQ / Nacos / Sentinel/ Seata / XXL-JOB / ElasticSearch / ELK / SkyWalking / canal / Sharding-JDBC

### 项目说明
**核心工作与成果**

1. 订单模块：基于 Sharding-JDBC 按用户 ID 分库分表，结合雪花算法与基因法生成订单号，支持多维度查询。

2. 使用 Canal 同步订单数据至 ElasticSearch，解决复杂查询与分析场景。

3. 通过 CompletableFuture 编排下单接口 （基本数据、风控、商品状态、优惠券、库存、其他规则等）异步校验任务，RT 从 260ms 降至 100ms。

4. 使用 XXL-JOB 分片任务优化超时关单流程，处理能力从 10 单/s 提升至 50 单/s。

5. 借鉴 Redis Key过期策略，基于定期设置 + 惰性设置结合的方式，解决优惠券过期状态设置的时间误差问题。

6. 商品模块：使用 Redis ZSET 实现热门商品排行榜，接口 RT 从 3s 优化至 20ms，数据库负载下降 10%。

7. 引入 ELK 与 SkyWalking，实现日志与链路全程可追溯。

8. 引入 RPA 自动化竞品价格监控与调价策略，价格竞争力提升 30%，月销售额增长 15%。
