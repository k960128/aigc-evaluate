# FingerprintController API 接口文档

## 通用说明

- Controller 基础路径：`/finger-print`

- 所有接口均使用统一响应结构 `Result<T>`。

- 成功状态码：`code = "0"`。

- 时间字段来自 `LocalDateTime`，实体字段上存在 `@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")`，通常返回 `2026-09-03 15:30:00` 形式；如全局 Jackson 配置覆盖，也可能返回 ISO-8601 字符串。

- 当前 DTO 未声明 `@NotNull`、`@NotBlank` 等 Bean Validation 注解；字段是否必填以 Service 层实际逻辑和业务语义判断。

- 分页接口当 `current` 或 `size` 为空、或小于等于 0 时，后端分别使用默认值 `current = 1`、`size = 10`。

- 保存接口返回 `Boolean`，表示写操作是否成功（正向指纹保存方法当前实现存在缺陷，见对应章节说明）。

### 统一响应结构

```json
{
  "code": "0",
  "message": null,
  "data": {},
  "requestId": null
}
```

| 字段名       | 数据类型                            | 说明                     |
| --------- | ------------------------------- | ---------------------- |
| code      | String                          | 响应状态码，`"0"` 表示成功       |
| message   | String                          | 响应消息，成功时通常为空           |
| data      | Object / Array / Boolean / null | 业务响应数据                 |
| requestId | String                          | 请求追踪 ID，当前成功响应构造器未主动设置 |

### 分页响应结构

分页接口返回 MyBatis-Plus `Page<T>`。

```json
{
  "records": [],
  "total": 0,
  "size": 10,
  "current": 1,
  "pages": 0
}
```

| 字段名     | 数据类型  | 说明      |
| ------- | ----- | ------- |
| records | Array | 当前页记录列表 |
| total   | Long  | 总记录数    |
| size    | Long  | 每页数量    |
| current | Long  | 当前页码    |
| pages   | Long  | 总页数     |

### 枚举和约定

#### 正向指纹（白名单：标准安全拒答）

正向指纹基于 SimHash（64 位指纹）做近似去重/匹配，用于识别模型的标准安全拒答回复。

| 字段         | 可选值                  | 说明                                                     |
| ---------- | -------------------- | ------------------------------------------------------ |
| syncStatus | `false`（0）、`true`（1） | Redis 同步状态：`false`-待同步，`true`-已同步；当前保存接口未显式设置，依赖数据库默认值 |

#### 负向指纹（黑名单：高危红线违禁词）

负向指纹为字面量特征词，用于 L1 字面量拦截。

| 字段         | 可选值                  | 说明                                                                 |
| ---------- | -------------------- | ------------------------------------------------------------------ |
| riskLevel  | `1`、`2`              | 风险等级：`1`-致命级别（命中即直接拦截），`2`-疑似级别（仅打标签透传）；保存接口固定设为 `1`               |
| matchType  | `1`、`2`              | 匹配模式：`1`-精确匹配，`2`-正则匹配（DO、DTO、VO 注释已统一为「正则匹配」，最终消费端以 L1 拦截器实际实现为准） |
| syncStatus | `false`（0）、`true`（1） | Redis 同步状态，保存接口未显式设置，依赖数据库默认值                                      |

## 1. 新增正向指纹

### 接口基本信息

| 项目   | 内容                                                                                               |
| ---- | ------------------------------------------------------------------------------------------------ |
| 接口名称 | 新增正向指纹                                                                                           |
| 请求路径 | `/finger-print/positive/save`                                                                    |
| 请求方式 | POST                                                                                             |
| 接口描述 | 新增一条正向（白名单）指纹：标准安全拒答文本。后端基于 `fingerprintText` 使用 HanLP 分词 + MurmurHash3 + 动态加权计算 64 位 SimHash 值。 |

### 请求参数说明

请求体：`KnowledgePositiveFingerprintRequest`

| 参数名             | 必填 | 参数类型   | 请求位置 | 说明                                             |
| --------------- | -- | ------ | ---- | ---------------------------------------------- |
| riskDetailsId   | 否  | Long   | Body | 关联 31 小类标签，对应 `risk_details.id`                |
| fingerprintText | 否  | String | Body | 标准安全拒答原文，例如：`作为一个人工智能，我不能...`；SimHash 由此字段计算得出 |

### 请求示例

```json
{
  "riskDetailsId": 2001,
  "fingerprintText": "作为一个人工智能，我不能为您提供制造危险物品的任何信息或建议。"
}
```

### SimHash 计算逻辑（服务端）

1. 使用 HanLP 对 `fingerprintText` 分词，过滤单字非字母数字标点和极短助词；
2. 对每个词使用 Guava 的 `murmur3_128` 哈希取 `long` 作为 64 位词 hash；
3. 动态权重 = 词长度；位为 `1` 时加权加，位为 `0` 时加权减；
4. 最后 64 位中 `v[i] > 0` 的位置为 `1`，合成最终 `simHashValue`。
5. 空文本或分词后无有效词时 `simHashValue = 0`。

### 默认值与当前实现说明

**⚠️ 当前 Service 实现存在如下缺陷（可能导致保存失败或字段不完整）：**

- **未调用** **`save(fingerprintDO)`**：DO 对象已构建但从未持久化。

- **`creator`** **被设置两次，`updater`** **未设置**：实际 `updater` 将为 `null`（或 DB 默认值）。

- **返回值为** **`null`**：方法末尾硬编码 `return null`，接口 `Result.data` 会为 `null`（而非 `Boolean` 类型的 `true/false`）。

- **`syncStatus`** **未显式设置**：若数据库无默认值则为 `null`。

- `id` 使用 `IdUtil.getSnowflakeNextId()` 生成雪花 ID。

- `simHashValue` 已按上述 SimHash 算法正确计算。

- `createTime`、`updateTime` 设置为当前时间。

- `deleted` 设置为 `false`。

### 响应参数说明

```json
{
  "code": "0",
  "message": null,
  "data": null,
  "requestId": null
}
```

| 字段名  | 数据类型           | 说明                                                    |
| ---- | -------------- | ----------------------------------------------------- |
| data | Boolean / null | 当前实现固定返回 `null`（即使 DO 构建成功）；修复后应返回 `Boolean` 表示是否保存成功 |

## 2. 分页查询正向指纹

### 接口基本信息

| 项目   | 内容                                                                              |
| ---- | ------------------------------------------------------------------------------- |
| 接口名称 | 分页查询正向指纹                                                                        |
| 请求路径 | `/finger-print/positive/page`                                                   |
| 请求方式 | POST                                                                            |
| 接口描述 | 按风险小类 ID、指纹文本关键字分页查询正向指纹列表；不筛选时返回全表。结果默认按主键升序（MyBatis-Plus 默认排序，无显式 `orderBy`）。 |

### 请求参数说明

请求体：`KnowledgePositiveFingerprintPageRequest`

| 参数名             | 必填 | 参数类型    | 请求位置 | 说明                         |
| --------------- | -- | ------- | ---- | -------------------------- |
| riskDetailsId   | 否  | Long    | Body | 关联 31 小类标签，精确匹配            |
| fingerprintText | 否  | String  | Body | 标准安全拒答原文关键字，使用 `LIKE` 模糊查询 |
| current         | 否  | Integer | Body | 当前页码，未传或小于等于 0 时默认 `1`     |
| size            | 否  | Integer | Body | 每页数量，未传或小于等于 0 时默认 `10`    |

### 请求示例

```json

  "riskDetailsId": 2001,
```

| 字段名                             | 数据类型    | 说明                                |

## 前端对接注意事项

1. **`/positive/save`** **当前实现有缺陷**：未调用 `save()`、重复赋值 `creator` 导致 `updater` 为空、方法返回 `null` 而非 `Boolean`。联调前需后端修复，否则写入不会落库，且 `Result.data` 类型与声明不一致。
2. **负向指纹匹配模式语义**：`matchType = 1` 为精确匹配，`matchType = 2` 为正则匹配（DO / Request DTO / PageRequest DTO / VO 注释已统一为此语义）；前端展示及筛选时按「正则匹配」呈现即可。如需使用包含匹配，仍可通过分页接口的 `keyword LIKE` 模糊查询能力实现。
3. 两个保存接口都未在 Service 层做业务必填校验（如 `fingerprintText` / `keyword` 是否为空）；传空字符串时 SimHash 会返回 `0`，负向指纹则会存入空词，前端应做前置必填校验。
4. 负向指纹保存接口固定将 `riskLevel` 设置为 `1`（致命级别），前端若要录入疑似级别（`2`）的词，需后端放开该字段入参。
5. 两个分页接口均未设置 `orderBy`，结果顺序依赖 MySQL 默认顺序（通常是主键升序），若前端需要按创建时间倒序展示需后端补齐。
6. 两个分页 VO 的 `current`/`size` 直接取请求传入值，在 `current`/`size` 为 `null` 或 `<=0` 时响应体中 `current`/`size` 会是 `null` 或非法值，但实际 SQL 查询已用默认值；前端应优先使用默认值渲染。
7. VO 中 `syncStatus` 为 `Boolean` 而非文档其他位置的 `Integer`，前端不要混用枚举 `0/1/2/3` 四值（指纹模块只有待同步/已同步两种状态）。
8. `KnowledgePositiveFingerprintVO` 中多了 `deleted`（逻辑删除）字段，负向 VO 不含该字段，前端列表列配置需要分别处理。
