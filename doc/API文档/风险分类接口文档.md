# RiskCategoryController API 接口文档

## 通用说明

- Controller 基础路径：`/risk/category`
- 所有接口均使用统一响应结构 `Result<T>`。
- 成功状态码：`code = "0"`。
- 时间字段来自 `LocalDateTime`，接口序列化通常为 ISO-8601 字符串，例如 `2026-06-08T15:30:00`；实体字段上存在 `@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")`，如项目全局 Jackson 配置生效，也可能返回 `2026-06-08 15:30:00`。
- 当前 Controller 未使用 `@Validated`，请求 Body 字段未声明 Bean Validation 注解；Body 内字段按源码校验结果标注为非必填，`@PathVariable` 和默认必填的 `@RequestParam` 参数按 Spring 规则标注为必填。
- 分页接口返回 MyBatis-Plus `Page<T>`；风险大类和风险明细分页均按 `sortOrder` 升序返回。

### 统一响应结构

```json
{
  "code": "0",
  "message": null,
  "data": {},
  "requestId": null
}
```

| 字段名 | 数据类型 | 说明 |
|---|---|---|
| code | String | 响应状态码，`"0"` 表示成功 |
| message | String | 响应消息，成功时通常为空 |
| data | Object / Array / Boolean / null | 业务响应数据 |
| requestId | String | 请求追踪 ID，当前成功响应构造器未主动设置 |

### 枚举和约定

| 字段 | 可选值 | 说明 |
|---|---|---|
| status | `0`、`1` | 业务状态：0-禁用，1-启用 |
| deleted | `false`、`true` | 逻辑删除标识；实体配置了 `@TableLogic` |

### 分页响应结构

分页接口返回 MyBatis-Plus `Page<T>`。

```json
{
  "records": [],
  "total": 0,
  "size": 10,
  "current": 1,
  "pages": 0
}
```

| 字段名 | 数据类型 | 说明 |
|---|---|---|
| records | Array | 当前页记录列表 |
| total | Long | 总记录数 |
| size | Long | 每页数量 |
| current | Long | 当前页码 |
| pages | Long | 总页数 |

## 1. 分页查询风险分类

| 项目 | 内容 |
|---|---|
| 接口名称 | 分页查询风险分类 |

| 请求方式 | GET |
| 接口描述 | 分页查询风险大类，支持按分类名称和业务状态筛选，结果按排序权重升序返回。 |

| status | 否 | Integer | Query | 业务状态：0-禁用，1-启用 |


## 前端对接注意事项

1. 风险分类和风险明细的新增、更新、删除接口当前均返回 `Boolean`，不返回变更后的实体详情；如需展示最新数据，操作成功后应重新查询详情或列表。
2. `status` 请统一按 `0` 禁用、`1` 启用渲染。
3. `/risk/category/details/list` 当前 Controller 不接收 `categoryId` 入参，前端不要按“按分类 ID 查询”假设传参生效。
4. 删除接口返回成功只表示后端删除操作执行成功；实体启用了逻辑删除字段，实际数据是否物理删除取决于 MyBatis-Plus 配置。
