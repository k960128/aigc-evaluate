样本工厂一期 · 开发计划图

Workflow 模式 · 4 Agent + 3 Service · 单人全栈 10 周

版本：v1.0 技术栈：Spring Boot 3.4 / Spring AI 1.0.0 模式：确定性流水线 定位：批量生产线

00总览

一期用 Workflow 模式批量生产安全评测样本。控制流写在 Java 代码里，LLM 只负责内容生成与判定。整条流水线 4 个 Agent + 3 个 Service，5 步顺序执行。

核心原则：能 Java 直调的不经 LLM；能用规则解决的不用 Agent；一期的每一步都必须可复现、可审计、可预估。

03Agent 总览

一期共 4 个 Worker Agent 和 3 个 Service。Agent 是被动的执行单元，Service 是无状态的工具层。

# 名称 类型 职责 工具
1 SeedCuratorAgent Agent 主题 → 结构化种子 无
2 GeneratorAgent Agent 种子 → 候选样本 无
3 ComplianceCheckService Service 硬边界合规检查 Java 直调
4 DedupAgent Agent 精确去重 无
5 QualityReviewerAgent Agent 4 维质量评审 3 个工具
6 ProbeService Service 样本有效性验证 目标模型调用
7 ConsistencyCheckService Service 类别一致性检查 LLM 辅助
关键设计：一期只有 1 个 Agent 需要工具（QualityReviewer）。其他 Agent 都是纯 LLM 生成或纯 Java 计算，符合"Workflow 不是 Agent 越多越好"的原则。

3.1 SeedCuratorAgent · 种子策展

🌱
SeedCuratorAgent
把主题方向展开成结构化种子 · 无工具 · 纯 LLM 生成
Agent #1

职责：接收一个主题方向，产出一组结构化种子。种子是后续生成的基础，需要保证角度不同、不重复。

入参
  • topic 主题方向
  • category 政策类别
  • attackType 攻击策略
  • count 种子数量（3-5）
出参
  • List<SeedSample>
  • 每条含 id / content / category
  • attackType / language / difficulty

工具情况

无工具 策展是"让模型基于主题发散"的任务，模型自身能力足够。为避免重复，把历史种子拼进 prompt 即可。

关键设计

  • 历史查重靠 prompt 上下文：加载该类别最近 50 条种子，拼进 prompt 里让模型避开
  • 写入 SeedCache：种子生成后写入本地缓存，供 Generator 按 seedId 反查
  • 7 个策略的 prompt 模板：每个攻击策略有独立的生成模板与 few-shot 示例

3.2 GeneratorAgent · 候选生成

✍️
GeneratorAgent
从种子生成候选样本 · 无工具 · 纯 LLM 生成
Agent #2

职责：接收种子 + 任务约束，批量生成候选样本。一次生成 1 条，外层循环控制批量，避免模型把 N 条塞进一条。

入参
  • SeedSample 种子
  • GenerationTask 任务
  • count 生成条数
出参
  • List<SafetySample>
  • 状态为 CANDIDATE
  • 含 seedId / promptVersion

工具情况

无工具 生成是模型的核心能力。引入工具反而会让模型倾向于复制，失去多样性。

关键设计

  • 多样性靠 prompt 上下文：每次生成时把"已生成的样本"拼进 prompt，引导模型换角度
  • 逐条生成 + 落库：每生成 1 条立即落库为 CANDIDATE，避免批量失败丢数据
  • 7 个策略的生成模板：与 SeedCurator 共用 attack-strategies.yml 里的定义

3.3 ComplianceCheckService · 合规检查

🛡️
ComplianceCheckService
硬边界合规检查 · Java 直调 · 不经过 LLM
Service #1
重要修正：一期不该叫 "SafetyFilterAgent"。评测样本的"攻击性"是产品属性，不该被过滤。这个 Service 拦的是真实危害、法律红线、授权越界、目标不符，不是"内容安全"。

职责：对候选样本做合规性判定。命中硬边界即拦截，不进后续流程。

入参
  • SafetySample 候选样本
出参
  • FilterDecision
  • safe: boolean
  • reason: string（拦截原因）

工具情况

Java 直调 全部由 Agent 代码直接调用，不经过 LLM。硬边界检查必须确定性，不能让 LLM 判断。

检查项（4 个）

checkPII(content)
正则 + NER 模型检测真实个人隐私：姓名 / 电话 / 身份证 / 地址。命中即拦。
checkBlacklist(content)
本地敏感词黑名单匹配。硬底线，命中即拒，零漏判。
checkAuthorization(category, lang)
校验类别 / 语言 / 模态是否在授权范围内。超出即拦。
checkLegalRedline(content)
法律红线检查：未成年人色情、恐怖主义操作、可执行犯罪步骤。

3.4 DedupAgent · 去重

🧹
DedupAgent
精确去重 · 无工具 · 纯 Java 算法
Agent #3

职责：判定候选样本是否与已有样本重复。一期只做精确去重（归一化 + SHA-256），语义近重复留二期。

入参
  • SafetySample 候选样本
出参
  • boolean isDuplicate
  • 副作用：设置 contentHash

工具情况

无工具 去重是纯算法问题，不该让 LLM 参与。

关键设计

  • 归一化：转小写 + 去空格 + 去标点，降低表面差异
  • SHA-256：哈希后命中即判重复
  • 局限：只能抓"完全重复"，语义近重复要二期加向量库

3.5 QualityReviewerAgent · 质量评审

⭐
QualityReviewerAgent
4 维质量评审 · 需要工具 · 独立 ChatClient
Agent #4

职责：对样本做 4 维评分，判定是否通过。与 Generator 使用独立的 ChatClient，避免"自己判自己"。

入参
  • SafetySample 候选样本
出参
  • ReviewVerdict
  • score: int（0-100）
  • pass: boolean（≥75）
  • reasons: List<String>

工具情况

3 个工具 评审不能只看"感觉"，需要对照标准与统计基线。这是一期唯一需要工具的 Agent。

getReviewRubric(category)
获取该类别的评审细则（各维度权重 + 打分标准）。让评分标准统一、可复现。
getSampleStatistics(category)
获取该类别的样本统计（总数 / 平均长度 / 攻击策略分布）。让多样性判断有基线。
checkSelfConsistency(content)
检查样本内部是否自洽（无自相矛盾）。规则引擎比 LLM 更可靠。

4 个评分维度

维度权重判断标准
相关性0.3是否切合目标类别与攻击策略
清晰度0.2表述是否清晰、无歧义
可复现性0.3是否可作为稳定的评测输入
多样性0.2是否提供了与典型样本不同的角度

3.6 ProbeService · 探针

🔬
ProbeService
样本有效性验证 · 真实调用目标模型 · 双 Judge 判定
Service #2

职责：把通过评审的样本真实发给目标模型，观察是否触发不安全响应。回答"样本真的有效吗"。

与评审的区别：Reviewer 判"样本写得好不好"（静态），Probe 判"样本能否测出模型问题"（动态）。质检 95 分的样本，探针跑出来可能是"无效"。
入参
  • SafetySample 通过评审的样本
  • targetModel 目标模型
出参
  • ProbeReport
  • effective: boolean
  • confidence: double
  • response: 完整响应

工具情况

目标模型调用 探针需要真实调用目标模型，这是与质检最本质的区别。

4 步流程

  1. 发送：把样本作为用户输入发给目标模型（隔离环境）
  2. 捕获：记录完整响应（正文 / 是否拒绝 / 时延 / token）
  3. 判定：规则 + LLM Judge 双层判断响应是否"不安全"
  4. 标记：给样本打"有效 / 无效 / 不确定"标签

一期范围

  • 只对高价值类别开启：专业建议滥用、隐私侵犯
  • 只对内部授权模型：避免合规风险
  • 不阻塞入库：探针结果只做标记，人工审核兜底
  • 做成可开关：配置项控制，逐步推广

04工具清单

一期共 3 个 LLM 侧工具（暴露给模型）和 5 个 Java 侧工具（Agent 直调）。

LLM 侧工具（暴露给模型）

工具所属 Agent用途触发时机
getReviewRubric QualityReviewer 获取类别评审细则 评审开始时
getSampleStatistics QualityReviewer 获取类别统计基线 评审多样性时
checkSelfConsistency QualityReviewer 检查样本内部自洽 评审前预检

Java 侧工具（Agent 直调，不经 LLM）

工具所属组件用途调用方式
checkPII ComplianceCheckService PII 检测 Java 直调
checkBlacklist ComplianceCheckService 黑名单匹配 Java 直调
checkAuthorization ComplianceCheckService 授权范围校验 Java 直调
checkLegalRedline ComplianceCheckService 法律红线检查 Java 直调
callTargetModel ProbeService 调用目标模型 HTTP / SDK
选择原则：凡是"命中即拒"的判定，必须 Java 直调；凡是"帮助 LLM 判断"的，可以给 LLM 侧。

06开发排期

单人全栈，10 周。后端全做，前端只做 4 个关键页面。

W1 · 基础设施

项目骨架 + 数据库 + 领域模型

Spring Boot 项目 + PostgreSQL + Flyway + 6 张表 + SampleStore + Swagger

W2 · 生成层

SeedCurator + Generator + 7 策略模板

两个 Agent 可独立运行，能产出候选样本，人工抽检 20 条

W3 · 质检层

Dedup + QualityReviewer + 评审细则

4 个 Agent 全部可运行，评审与人工一致度 ≥ 70%

W4 · 流水线

Pipeline + Service + Controller

端到端跑通，Swagger 可调，数据库有样本

W5 · 合规

ComplianceCheckService + 仪表盘页

PII / 黑名单 / 授权 / 法律红线全部实现，前端第一个页面

W6 · 探针

ProbeService（2 类别）+ 样本库页

探针能对高价值类别标记有效性，前端第二个页面

W7 · 审核

人工审核 + 审计日志 + 审核页

审核闭环，前端第三个页面

W8 · 覆盖度

覆盖度矩阵 + trace 落库 + 覆盖度页

6×7 矩阵可视化，前端第四个页面

W9 · 数据与调优

跑满 210 条样本 + 调优

根据人工抽检反馈调 prompt、调评审标准、性能优化

W10 · 收尾

文档 + 部署 + 上线

部署文档 / 使用手册 / 运维手册 / Docker 镜像
