## 1. 产品定位与设计原则

建设一个面向安全运营专家和应用研发团队的安全评测工作台，支持标准评测、自动红队探索、样本生产，持续完成风险发现、证据验证、用例沉淀与修复回归。

用户可以直接使用已有数据集，也可以让攻击智能体在限定目标和预算内探索弱点。发现的问题必须能够解释测试条件、给出证据，并进入复核和回归流程。

当前业务设计原则：

1. 保留标准评测与样本运营，增加独立的自动红队探索任务。
2. 自动红队的主要产物是风险发现及证据；样本数量是过程指标。
3. 支持静态单轮、自适应单轮搜索、自适应多轮对话，明确三者不同的会话语义。
4. 动态测试输入可以在已授权范围内直接执行并留痕；进入正式资产库仍需审核。
5. eval-agent 管理规划和攻击循环；eval 提供统一的目标执行、判定及事实记录能力。
6. newpipeline 继续承担现有批量执行。会话运行需要扩展共享底座，不再要求每次探测先落入正式数据集。
7. 保留确定性编排器、权限、预算、状态机、检查点和证据引用，所有模型建议经过代码校验。
8. 采用业务角色驱动的 Agent 拆分；生成、质检、报告等能力可以是有界工作流。
9. Spring AI 继续作为当前实现基础，框架升级、AgentScope-Java 迁移和微服务拆分均不是本次业务建设的前置条件。
10. 本文统一定义业务职责、系统边界、开发顺序与验收标准。实际接入需要兼容已有契约和在途任务；页面 Mock 不能替代真实能力验收。

### 1.1 目标用户与成功标准

| 用户 | 主要工作 | 希望获得的结果 |
| --- | --- | --- |
| 安全运营专家 | 配置风险目标、种子和策略，复核发现，管理用例 | 有效发现增加，重复劳动减少，结论可追溯 |
| 应用研发人员 | 接入模型或应用，定位问题，提交修复版本 | 能复现问题，知道修复后是否仍存在 |
| 评测负责人 | 制定标准、检查覆盖和成本、确认报告 | 指标口径稳定，测试范围和局限清楚 |

有效发现数、人工复核准确度、复现结果和回归效率是核心指标。Agent 数量、生成样本量、对话轮数不能单独证明产品价值。

### 1.2 与外部框架的关系

| 参考对象 | 值得吸收的产品能力 | 我们的落点 |
| --- | --- | --- |
| PyRIT | 组合攻击、目标适配、评分、会话和实验留痕 | 策略注册、执行适配、会话记录 |
| Promptfoo | 风险类型与攻击方式分离、自适应探索、回归与研发集成 | 风险目录、策略目录、回归用例和版本对比 |
| DeepTeam | 按漏洞组织攻击和专属评估指标、应用接入 | 风险成功判据、目标能力声明、判定路由 |

界面、记忆和智能体不是独有优势。我们的建设重点是将这些测试能力与现有流水线、专家样本运营和企业证据流程衔接。没有在本项目对三款框架进行同条件效果实验，本文不声称攻击效果优于它们。

## 2. 业务模型：三类任务与一个风险处理流程

### 2.1 三类任务

| 类型及建议编码 | 用户输入 | 是否调用被测目标 | 主要产物 | 典型入口 |
| --- | --- | --- | --- | --- |
| 标准评测 STANDARD_EVALUATION | 目标快照、正式用例集版本、规则版本 | 是 | 用例执行结果、风险分布、版本差异 | 标准评测 |
| 自动红队 RED_TEAM_EXPLORATION | 目标、风险范围、策略、模式、预算；种子可选 | 是 | 会话、探测轨迹、疑似发现和证据 | 自动红队 |
| 样本生产 SAMPLE_PRODUCTION | 种子或案例、变异要求、数量与质量要求 | 否 | 候选样本、质量结论和审核记录 | 样本工厂 |

样本生产中的“否”仅指不调用被测目标；生成和质检仍可能调用模型并产生费用。若用户要检验生成样本的攻击效果，应显式创建关联评测任务。

修复回归是标准评测的一种运行用途，通过 BASELINE（基准）或 REGRESSION（修复回归）区分，不再增加第四套任务系统。动态策略再探索可以关联同一问题，但其统计不能替代固定用例回归。

三类任务可以独立运行。评测活动用于组合相关任务、共享范围和汇总结果，创建单个任务时可由系统自动建立活动，用户无需先理解多层对象。

### 2.2 攻击模式与计数单位

| 模式 | 运行方式 | 需要保存的内容 |
| --- | --- | --- |
| STATIC_SINGLE_TURN 静态单轮 | 每条输入在独立、干净的目标上下文中执行 | 输入、回复、目标快照、判定 |
| ADAPTIVE_SINGLE_TURN 自适应单轮搜索 | 攻击者根据历史尝试改写下一条输入；目标每次从干净上下文开始 | 尝试之间的变异关系及每次执行 |
| ADAPTIVE_MULTI_TURN 自适应多轮 | 在同一目标会话中，根据上一轮回复产生下一轮输入 | 会话、每轮消息、分支、目标状态和判定 |

- 攻击尝试 Attempt：围绕一个风险目标、策略和目标快照开展的一次探索单元。
- 目标会话 Session：目标侧的一段上下文。单轮模式每次探测使用新的逻辑会话；多轮模式可以连续多次探测。
- 探测 Probe：向目标提交一次输入或一次受控场景刺激，并记录对应响应。重试不能伪装成新发现，实际物理调用单独计数。
- 分支 Branch：从某个已记录节点开始的另一条攻击路径。能否复制、回退目标状态取决于适配器能力。
- 多批次迭代：完成一批后生成另一批，与同一会话内多轮交互不同。

不能用“已执行 100 个样本”同时表示 100 次调用、100 个会话和 100 个独立用例。

### 2.3 风险处理流程

三类任务共享风险与资产管理能力。动态探测不强制经过样本工厂；发现沉淀为正式用例时进入审核。

~~~mermaid
flowchart TB
    U["安全专家 / 应用研发"] --> W["统一评测工作台"]
    W --> B["标准评测：固定用例集"]
    W --> R["自动红队：受约束动态探索"]
    W --> P["样本工厂：种子生成与变异"]
    P --> Q["质量检查与人工审核"]
    Q --> A["正式用例资产：版本化"]
    A --> B
    B --> E["执行结果与证据"]
    R --> E
    E --> F["疑似风险：归并与复核"]
    F --> V["复现验证与人工确认"]
    V --> I["确认发现：研发修复"]
    V --> C["候选回归用例"]

~~~

## 3. 一次自动红队任务如何运行

### 3.1 创建与启动

用户选择目标、环境和测试身份，配置风险范围、执行模式、策略、预算与停止条件。可以手工配置，也可以用自然语言生成可编辑草案。

系统先验证目标能力和风险所需证据。例如，只有文本回复的接口不能被当作“已验证工具越权”的完整测试环境。缺少能力时明确拒绝该项测试或标记不支持，不能静默降级并声称已覆盖。

规划智能体输出有限的攻击尝试清单和策略配置。简单任务可以使用固定模板，无需每次调用规划模型。批准的配置保存为不可变版本，并关联授权记录。

审批策略支持事先授权范围内自动启动；不是每次任务都必须人工批准。修改目标、身份、风险边界、允许动作或提高预算时，重新校验并依据审批策略更新授权。

### 3.2 自适应执行闭环

~~~mermaid
flowchart TD
    A["已授权任务与配置快照"] --> B["创建尝试 / 准备会话"]
    B --> C["攻击智能体提出下一步动作"]
    C --> D{"范围、能力、状态和预算校验"}
    D -->|不通过| X["拒绝动作：有限修正或停止"]
    X --> C
    D -->|通过| E["预留预算并持久化探测意图"]
    E --> F["共享执行服务调用被测目标"]
    F --> G{"执行结果"}
    G -->|结果未知| H["核对执行状态；无法确认则阻塞该会话"]
    G -->|明确失败| I["记录错误；按规则重试或结束"]
    G -->|响应已确认| J["保存响应 / 工具轨迹 / 环境证据"]
    J --> K["按风险规则进行探测或会话判定"]
    K --> L{"是否存在疑似风险"}
    L -->|是| M["建立发现并安排复核 / 复现"]
    L -->|否或待定| N{"是否继续"}
    M --> N
    N -->|继续当前会话| C
    N -->|新尝试或新会话| B
    N -->|结束| O["执行结束：保存停止原因和覆盖缺口"]
    O --> P["汇总已确认、待复核和无法判断的结果"]
~~~

图中有限修正、重试、新尝试均消耗相应预算。停止检查发生在每次模型调用和目标调用之前，不能等循环末尾才检查。

### 3.3 示例：客服隐私边界

在测试环境中为身份 A、身份 B 准备虚构订单，明确 A 不应访问 B 的信息。

任务选择隐私泄露风险和多轮模式。攻击智能体根据目标回复继续探索；执行层保存实际检索与工具调用证据；判定层区分模型虚构订单、拒绝回答、以及真实读取了不应访问的数据。

若发现疑似越权，验证流程在新的干净会话和相同身份条件下按记录步骤复现。报告同时保留最初证据和后续复现结果。经审核的案例包含身份、数据准备、会话步骤和断言，进入回归库。

研发更改权限校验后，使用新目标快照运行该用例并记录结果。一次回归未复现不能自动推导出所有同类风险已消失。

### 3.4 样本工厂与标准评测

样本工厂继续支持：配置种子和计划时间，批量生成，质量检查与去重，第二天人工查看并批准进入正式用例集。失败和低质量样本保留原因，不能为了完成数量目标放宽准入标准。

标准评测固定目标配置、用例集版本、规则版本与运行设置。原有单样本文本任务继续走 newpipeline；对新型会话用例，按用例类型路由至共享底座的会话执行能力，不强塞进单文本字段。

## 4. 风险、策略、目标与成功判据

### 4.1 四个概念分别配置

| 概念 | 回答的问题 | 示例 |
| --- | --- | --- |
| 风险 Risk | 什么行为不应该发生 | 未授权用户读取其他用户资料 |
| 攻击技术 Technique | 用哪类方法探测 | 角色包装、上下文诱导、间接指令 |
| 执行策略 Strategy | 如何组织尝试与反馈 | 静态变异、迭代搜索、多轮推进、受控分支 |
| 成功判据 SuccessCriterion | 看到什么证据才算命中 | 实际返回预先标记的非授权测试数据 |

风险目录管理定义、适用目标、所需证据和规则版本。策略目录管理支持的模式、参数、默认预算、必需能力和停止规则。配置必须版本化。

OWASP、MITRE 等可以作为分类映射，映射本身不等于通过认证或满足全部合规要求。

### 4.2 目标能力声明

目标登记至少区分 MODEL（模型接口）、CHAT_APPLICATION（聊天应用）、RAG_APPLICATION（检索应用）、TOOL_AGENT（工具型应用）。这些是适配分类，不保证所有类型已实现。

| 能力 | 需要明确的事实 | 不具备时的处理 |
| --- | --- | --- |
| 对话上下文 | 无状态消息重放，或目标服务维护会话 | 不支持多轮则禁用相关模式 |
| 重置与分支 | 可重置会话、可重放、可复制状态的范围 | 不允许伪造回退或分支成功 |
| 测试身份 | 身份引用、角色、租户和可访问测试资源 | 无法验证权限类结论 |
| 工具及检索证据 | 能获得哪些调用、检索与实际执行记录 | 标记证据缺口或降低结论范围 |
| 场景准备 | 是否支持测试文档、知识库内容或页面夹具 | 不把普通聊天输入冒充间接注入测试 |
| 外部影响控制 | 允许操作的测试资源及状态清理方式 | 禁用未授权的状态变更 |

模型、系统提示词、参数、应用构建版本、知识库版本、测试身份和环境共同构成目标快照。无法获得某项版本时标明未知和复现限制，不能编造快照。

### 4.3 运行授权与正式入库分开

运行授权约束目标、环境、身份、风险、动作和预算。动态输入在此范围内执行并记录，不自动成为正式资产。

正式入库审核检查测试价值、分类、证据、去重、前置条件和可复用性。测试用例、经验和规则修改分别审核；批准一个用例不等于批准自动修改 Judge 规则。

## 5. 智能体与工作流的职责

### 5.1 角色与架构选择

| 角色 / 建议名称 | 负责什么 | 输入 → 输出 | 推荐架构 |
| --- | --- | --- | --- |
| 评测规划 EvaluationPlannerAgent | 将意图转成有限计划，按覆盖和反馈调整任务分配 | 意图、资源与预算 → 计划草案或调整建议 | Supervisor + Plan-and-Execute；模板可替代简单规划 |
| 动态攻击 AdaptiveAttackAgent | 基于当前目标反馈选择下一次输入或结束尝试 | 策略、会话、判定反馈、预算 → AttackAction | 受约束 ReAct；持久化循环由 Java 驱动 |
| 样本生成 SampleGenerationWorkflow | 根据种子和策略生成候选内容，接受有限质量反馈 | 种子、约束 → 候选样本 | 结构化生成 + 有界改写 |
| 样本质量 SampleQualityWorkflow | 检查偏题、重复、可执行性和资产准入 | 候选样本、标准 → 通过、修改、拒绝或待人工 | 确定性校验 + Evaluator-Optimizer |
| 独立复核 FindingVerifier | 检查证据与规则是否支持结论，建议复现方案 | 原始事实、规则 → 复核意见与复现需求 | 独立结构化评价；必要时有界工具检索 |
| 结果分析与报告 EvaluationAnalysisWorkflow | 解释代码统计、整理发现和覆盖缺口，生成报告 | 事实、确认状态、统计 → 分析和报告 | 固定工作流；必要时按风险并行分析 |
| 经验整理 ExperienceCurationWorkflow | 提炼有证据来源的策略经验，提交审核 | 已复核案例 → 候选经验 | 检索与结构化归纳 |

“角色”不是必须一一对应独立微服务或自主 Agent。规划和攻击需要根据反馈决策；生成、质检、报告可以是短流程。复核不是第二套默认 Judge。

### 5.2 规划与攻击的两层循环

规划层决定安排哪些风险目标、策略和尝试，何时补充覆盖。它不必在每个探测后调用一次大模型，可以在尝试结束、出现新发现或覆盖不足时运行。

攻击层只在指定尝试内决定下一步。它不能自行扩大风险范围、更换授权身份、增加预算或触发任意工具。

允许的动作见第 9 节。攻击者的“我已经成功”只是建议；风险判定使用实际证据和独立规则。持久化数据只保存结构化动作、简短依据和观察引用，不将模型内部推理链作为审计事实。

### 5.3 编排器与业务角色如何协作

EvaluationOrchestrator 是确定性业务编排器，负责持久化状态、授权、预算和调度。规划与攻击角色提供建议，不能自行修改执行事实或跳过业务校验。

| 执行节点 | 决策或处理主体 | 编排器负责的约束 |
| --- | --- | --- |
| 生成计划 | EvaluationPlannerAgent 或固定模板 | 校验资源、能力、范围和预算，固定计划版本并关联授权 |
| 提出下一步攻击 | AdaptiveAttackAgent | 校验 AttackAction，先记录意图与预算预留，再交共享执行层调用目标 |
| 生成与修订样本 | SampleGenerationWorkflow + SampleQualityWorkflow | 限制迭代次数、去重、保存来源，只有审核通过才启用正式用例 |
| 复核与复现 | FindingVerifier + ReplayService | 分别保存意见和新执行记录，复现调用纳入授权预算 |
| 汇总与报告 | EvaluationAnalysisWorkflow | 以代码统计和证据为输入，报告确认后固定快照 |
| 整理共享经验 | ExperienceCurationWorkflow | 核对来源，经过审核与权限校验后才供其他任务检索 |

重构时可保留 EvaluationSupervisorAgent.proposePlan 的契约思路，或由 EvaluationPlannerAgent 承接规划职责；旧 eval-agent 实现已清理，不能把旧类名当作当前可用接口。是否继续拆分策略选择、报告或质检类，由职责和独立验收需要决定，不以 Agent 数量作为交付目标。

### 5.4 模型配置隔离

规划、攻击、样本生成、Judge、复核分别配置模型与提示词版本；被测目标独立配置。角色隔离不要求购买五种不同模型，但同模型的交叉复核不能声称完全独立。

候选模型先在中文、结构化输出、工具调用和任务效果上进行小规模验证。攻击模型拒绝生成、返回无效格式或重复无价值输入时，分别记录生成失败、契约失败或低质量，有限重试或使用已配置备选模型；不能记作目标安全拒答，也不以训练专用模型为前置条件。

## 8. 判定、复核、复现和修复

### 8.1 三种判定范围

| 范围 | 输入 | 输出解释 |
| --- | --- | --- |
| PROBE 单次探测 | 本次输入、回复及必要上下文 | 此次交互是否观察到风险 |
| SESSION 完整会话 | 会话轨迹、对应规则、过程证据 | 多轮组合是否满足风险成功判据 |
| SCENARIO 应用场景 | 对话、测试身份、检索及工具实际执行证据 | 应用权限或行为边界是否被突破 |

统一判定结果为 RISK_OBSERVED（观察到风险）、NO_RISK_OBSERVED（本次未观察到）、INCONCLUSIVE（证据不足或冲突）、NOT_APPLICABLE（规则不适用）。这不等同于系统整体安全。

L1 的单次拒答命中可以形成该次观察，不能直接结束整个多轮任务并判为安全。调用失败、评分失败、攻击者生成失败分别记录执行状态，不冒充 NO_RISK_OBSERVED。

### 8.2 判定链与复核链

1. 判定服务依据风险规则和范围选择证据及可用判定器，输出追加式 Assessment。
2. 发现服务将相关命中归并为 Finding，保留每次命中的证据引用。
3. FindingVerifier 独立检查事实、规则和证据是否匹配，可输出支持、反对、证据不足或建议复现。
4. ReplayService 按已批准条件发起新的执行记录，不能仅让同一个 Judge 再读一次文本就称为复现。
5. 人工或预先配置的确定性复核策略更新发现的确认状态，保留原判定和不同意见。严重或争议发现按审批规则交人工。

Judge 和复核所读的目标响应、检索内容均是待分析数据，不是执行指令。结构校验、证据引用校验与模型隔离必须位于业务层。

### 8.3 两种重放

- 固定轨迹重放：在相同前置条件与干净会话中，按原输入序列执行，检查已定义断言。失败也可能与目标随机性或环境差异有关。
- 策略重跑：固定策略、规则、预算与目标配置，允许攻击者再次动态探索。属于新的探索，不能当作完全相同用例的回归。

回归用例可以保存固定消息序列，或带版本的确定性分支条件；不能把新一轮自由生成的输入混入原固定用例而仍标记“相同用例”。

### 8.4 发现与修复状态

确认状态和整改状态分别管理。发现可处于 SUSPECTED（疑似）、CONFIRMED（证据已确认）、DISMISSED（误报）、INCONCLUSIVE（无法确认），并单独保存复现记录。

已确认发现的整改流程为 OPEN（待处理）、IN_PROGRESS（处理中）、READY_FOR_RETEST（待回归）、RESOLVED（已验证修复）、REOPENED（再次出现）、ACCEPTED_RISK（接受风险）。接受风险需负责人和依据，不计为技术修复。

“复核支持”和“复现成功”分别显示；充分原始证据可能支持确认，即使后续未复现。关闭问题依据预先确定的回归标准和责任人确认，不由报告模型自动关闭。

当前产品原型将确认修复限定到当前指定的回归任务和修复目标快照：固定用例必须全部有明确的无风险观察结果，不能含未执行、待定、未知或调用失败项。负责人必须填写确认依据；历史通过记录不能替代新回归。确认只是本次固定范围内的结论，不推导为目标整体安全。

已确认问题在固定回归中再次命中时重新打开并追加发生记录。人工重新打开已修复或已接受风险的问题时，必须填写负责人和依据，并使旧修复依据失效；再次确认修复需要新回归。接受风险必须单独留痕，不计技术修复。

### 9.4 BudgetPolicy：执行预算

| 字段 | 类型 / 必填 | 含义与约束 |
| --- | --- | --- |
| maxTargetCalls | Integer / 目标测试必填 | 目标实际请求次数上限，包含重试与复现；预留验证额度 |
| maxAgentCalls | Integer / 是 | 规划、攻击、生成、质检、Judge、复核及报告的模型调用总上限，子类分别记账 |
| maxAttempts | Integer / 红队必填 | 最大攻击尝试数 |
| maxTurnsPerSession | Integer / 多轮必填 | 单会话可接受的新输入轮数上限 |
| maxTokens | Long / 是 | 所有可计量模型的输入输出 Token 总预算；逐次预留并结算 |
| maxCost / currency | Decimal + String / 否 | 费用上限与统一币种；仅在定价和计量可用时声称可强制 |
| maxDurationSeconds | Long / 是 | 从启动计时的最长运行时间；暂停不延长期限，需要时修订授权 |
| maxConcurrentSessions | Integer / 红队必填 | 同时运行的会话上限；单会话内请求仍保持顺序 |
| maxRetriesPerOperation | Integer / 是 | 每个操作的最大重试次数，可以为零 |

所有上限为非负值；不能使用负数表示无限。必需能力对应上限为零时，该动作不可执行。总预算可以设置子额度，但并发任务必须共同受总账约束。

服务不返回 Token 用量时，保存可识别的估算和误差说明，仍强制调用次数、输入长度及输出限制。无法保障某项硬预算的适配器应拒绝该配置，不能声称已强制精确费用。

当前 D02 的 MODEL 静态单轮适配器没有供应商 Token 返回值，因此使用统一的字符级估算并将计量来源标记为 `ESTIMATED`；输入 Token 在目标调用前预留，响应返回后结算，无法完整结算时运行进入 `BLOCKED`。D02 的 `maxTokens` 必须大于零，`maxCost` 当前必须为空；由于没有统一定价目录和费用计量，服务会在创建任务时拒绝费用预算，而不是返回一个未生效的费用上限。

## 10. 状态、异步、恢复与预算

### 10.1 执行状态与复核状态分离

任务执行状态建议如下；样本审核、发现复核和报告确认各有独立状态，不混在一个巨大的任务枚举中。

~~~mermaid
stateDiagram-v2
    [*] --> DRAFT
    DRAFT --> PLANNING
    PLANNING --> WAITING_APPROVAL
    PLANNING --> READY
    WAITING_APPROVAL --> READY
    WAITING_APPROVAL --> CANCELLED
    READY --> QUEUED
    QUEUED --> RUNNING
    QUEUED --> CANCELLED
    RUNNING --> PAUSING
    PAUSING --> PAUSED
    PAUSED --> QUEUED
    RUNNING --> BLOCKED
    BLOCKED --> QUEUED
    RUNNING --> STOPPING
    PAUSED --> STOPPING
    BLOCKED --> STOPPING
    STOPPING --> STOPPED
    RUNNING --> COMPLETED
    RUNNING --> FAILED
    PLANNING --> FAILED
    COMPLETED --> [*]
    STOPPED --> [*]
    CANCELLED --> [*]
    FAILED --> [*]
~~~

| 状态 | 含义 |
| --- | --- |
| DRAFT / PLANNING | 草案 / 正在形成计划 |
| WAITING_APPROVAL / READY | 等待所需审批 / 已满足启动条件 |
| QUEUED / RUNNING | 已持久化并排队 / 正在执行 |
| PAUSING / PAUSED | 停止调度新动作并等待在途调用结束 / 已到达可恢复检查点 |
| BLOCKED | 因结果未知、证据或目标状态需要核对而不能继续 |
| STOPPING / STOPPED | 正在终止调度并收敛在途状态 / 已停止，可能已有部分结果 |
| COMPLETED | 按本次执行策略正常结束，可仍有待复核发现 |
| FAILED | 因不可恢复的执行错误结束，保留部分结果 |
| CANCELLED | 启动前撤销或审批拒绝 |

状态图展示主路径；实现时补充启动前各状态的撤销、审批退回草案和超时转移，不能对非法转移静默成功。终态重跑创建新 runId，不把原运行改回 RUNNING。

运行状态、停止原因、覆盖完成度、复核进度分别展示。预算用尽是明确停止原因；可以正常结束一次有界探索，但不能因此显示“已完成全部覆盖”或“目标安全”。

### 10.2 异步与检查点

创建、启动、暂停等请求只完成校验和命令受理。后台工作者执行任务，持久化状态和事件。SSE 负责通知，不承担唯一状态存储；断线后从事件游标补发。

每次外部调用至少保存：操作标识、请求内容引用、授权版本、预算预留、幂等键和执行状态。响应确认后保存证据、结算消耗，再推进下一步。

工作者通过租约与版本校验争取执行权，避免多个实例同时推进同一会话。数据库事实为恢复依据，Redis 可以加速但不能独占关键状态。可靠投递可使用 outbox 或已有等效机制，由研发结合现有 MQ 实现。

### 10.3 重试与未知结果

| 情况 | 行为 |
| --- | --- |
| 明确未发出的失败 | 按配置有限重试，重新校验预算 |
| 已受理且目标支持幂等 | 使用同一操作键查询或重试；参数不一致必须拒绝 |
| 超时但目标可能已经执行 | 标记 UNKNOWN，优先查询目标；不能直接再发一条造成重复工具操作 |
| 无法确认目标状态 | 阻塞受影响会话；依据授权重置后新建尝试或转人工，保留原未知记录 |
| 目标会话过期 | 明确重新开始或验证重放条件，不能声称无缝续跑 |
| Judge 失败 | 重试判定，保留原目标响应；不重复目标调用，也不输出安全结论 |
| 用户停止后迟到响应 | 保存真实响应和费用，禁止再安排下一次攻击 |

不承诺跨任意外部目标的严格“恰好执行一次”。必须通过受控重试、幂等能力声明和未知状态处理管理实际语义。

### 10.4 预算与停止

预算在动作前原子预留，响应后结算；生成、Judge、复核、复现、失败重试都不能成为账外操作。预留报告和必要复核额度，避免探索耗尽所有资源后无法解释结果。

停止优先级：授权撤销或用户停止 > 硬预算与期限 > 无法安全推进的执行状态 > 预先配置的成功、无进展或覆盖规则。单个风险命中可以结束当前尝试，是否终止整个任务由任务配置决定。

暂停期间仍接收在途结果；恢复前重验授权、剩余期限与目标会话状态。取消请求无法保证撤销已经在目标发生的操作，界面必须显示仍在收敛的请求。

## 11. 记忆、经验与评测隔离

| 层次 | 存什么 | 使用规则 |
| --- | --- | --- |
| 运行事实 | 任务、会话、探测、证据、账目和检查点 | 可恢复的权威数据，不依赖聊天历史 |
| 攻击工作记忆 | 当前尝试的轨迹、失败方式、有效观察 | 当前任务内可即时使用；隔离租户、身份和会话 |
| 任务内策略摘要 | 本次运行哪些策略有效、哪些重复 | 帮助分配后续尝试；标明尚未复核 |
| 共享经验 | 审核后的策略模式、适用目标、限制和证据 | 带版本、来源、失效状态和访问权限 |
| 规则与用例资产 | 正式风险规则、用例集和历史结果 | 按授权和测试模式读取 |

攻击者记忆不直接注入 Judge；Judge 读取判据所需的事实，避免把攻击者主张当成证据。上下文压缩只改变模型所见摘要，不丢弃原始记录。

盲测或固定基准测试禁止检索其隐藏答案及保留测试集内容。探索发现纳入回归库时生成新版本；原基准版本不随运行自动变化。经验失效和规则修订要显式发布，防止旧目标行为被当成新版本事实。

## 12. 前端入口与操作流程

### 12.1 菜单

| 页面 | 用户操作 | 关键展示 |
| --- | --- | --- |
| 评测工作台 | 新建标准评测、自动红队或样本生产，继续未完成工作 | 三类任务、待处理事项、费用和最近风险 |
| 自动红队 | 配置目标与策略，查看计划并启动 | 目标能力、风险范围、攻击模式、预算、授权 |
| 标准评测 | 选择用例集版本，执行基准或修复回归 | 固定配置、运行结果、版本对比 |
| 样本工厂 | 配置种子、数量、变异与定时生成 | 批次、血缘、质检、通过或退回 |
| 风险发现 | 查看证据、复核、复现、分配整改、发起回归 | 确认状态、严重度、复现次数、整改状态 |
| 用例与策略资产 | 审核用例、维护版本、配置策略模板 | 适用目标、来源、覆盖、启用状态 |
| 目标与规则 | 管理目标能力、环境、身份引用和风险定义 | 快照、版本、可用性与证据支持 |
| 报告与待办 | 查看报告、处理审批和复核任务 | 已确认、待确认、未覆盖和报告版本 |

统一创建入口按任务类型展开字段，不要求用户依次进入多个 Agent 页面。所有关键操作都有明确按钮与状态，不依赖聊天窗口。

### 12.2 自动红队详情页

页面顶部展示任务类型、目标快照、风险范围、模式、状态和停止原因。

- 左侧：按风险和策略组织的尝试、会话与分支列表。
- 中间：当前会话的输入、目标回复、探测状态和证据入口。
- 右侧：当前判定、疑似发现、复核意见以及简短动作依据。
- 底部或固定状态栏：调用次数、Token、费用、剩余预算、执行期限与运行事件。

暂停、恢复、停止、查看原始证据和发起复现的可用性由服务端状态与权限决定。停止中不立即显示已停止；界面区分无风险观察、调用错误、证据缺失和未执行。

### 12.3 自然语言入口

自然语言用于生成任务草案、解释计划、追问结果。由系统提取结构化字段并展示给用户修改；执行仍遵守任务授权策略。对话不能默默增加预算、改变目标身份或把未审核案例启用。

运行详情展示可审计动作与观察摘要，不展示模型内部思维链，也不把流式聊天结束当作任务完成。

### 12.4 风险详情与修复回归

风险详情至少包含：风险定义、受影响快照、首次及后续发生记录、证据、独立意见、复现条件与结果、负责人、整改记录、关联用例及各版本回归。

“申请复现”“确认或驳回”“生成候选用例”“发起回归”是独立动作。复现会实际调用目标，须展示其消耗范围并计入授权；批准入库不会自动启动测试。

### 12.5 当前产品原型与正式实现的关系

[HTML 原型](red-team-agent-frontend-design.html)已提供本节八个业务入口。操作和数据结构见[Mock 使用说明](红队页面-Mock使用说明.md)。原型用于确认交互与业务衔接，正式实现仍按第 13～16 节的契约和验收要求开发。

| 能力 | 当前原型 | 正式实现要求 |
| --- | --- | --- |
| 任务与运行 | 用一个本地任务对象展示一次演示运行 | 任务、配置版本、runId 分开建模，重跑保留原运行 |
| 计划与授权 | 手工配置或本地关键词填草案，新增计划手工批准 | 按授权策略审批；规划结果经结构化校验，不隐式扩大范围 |
| 红队与样本执行 | 按钮逐次推进、预置响应、固定模拟用量 | 后台工作者自动推进，调用真实模型与目标，持久化事实与账目 |
| 定时与异步 | 手动触发计划、延迟模拟状态变化 | 可靠调度、幂等受理、检查点恢复、SSE 续订与未知结果核对 |
| 标准评测与回归 | 可模拟风险、无风险观察、未知、Judge 失败和目标调用失败；保存当前回归引用并展示版本对比 | 固定用例逐项执行并真实判定，完整回归后按规则确认修复 |
| 报告与资产 | 本地审核、历史留痕、规则和证据快照；页面与 Markdown 导出使用同一正文 | 服务端权限、版本管理、证据引用和发布规则 |
| 覆盖指标 | 展示所选风险的演示执行记录 | 按风险 × 策略及必需证据计算覆盖，独立记录未覆盖项 |

原型的 localStorage、Mock action 名称、固定预算增量及简化状态转移只用于演示，不能直接作为生产数据库、API 或执行机制。

### 12.6 原型业务一致性规则

- 多风险任务必须实际轮换风险；预算不足时保留未覆盖项。静态单轮不读取历史反馈，自适应单轮只读取同风险的历史尝试，多轮只延续当前会话上下文。
- 会话摘要保守聚合。未知、调用失败或判定待定不能显示为“未观察到风险”。
- 候选生成和正式入库沿用原始规则、条件、步骤和证据引用；标准评测发现缺少原始用例或结果时拒绝生成占位候选。
- 候选每次修改、退回和审核保存操作前后内容及意见，批准后形成正式资产版本。
- 待办覆盖计划授权、未知结果核对、风险复核、候选审核与修改、经验审核、结果跟进和报告确认。关闭结果跟进待办不改变原判定或回归资格。
- 报告确认时冻结关联会话、结果、发现、复现和回归上下文。旧报告缺少字段时展示限制，不从当前状态补写历史。

原型仍不演示跨策略自动规划、实际模型生成与质检、分布式调度、SSE、权限审批策略、真实分支会话、发现归并拆分和 CI 集成。这些正式能力要求仍保留在 D01～D07 中，不以原型完成代替验收。

## 13. API 与事件的产品契约

以下为建议路由，最终前缀与现有接口规范对齐。它们描述交互需求，不声称后端已经提供。

| 操作 | 建议接口 | 返回语义 |
| --- | --- | --- |
| 创建任务草案 | POST /api/evaluation-tasks | 返回 taskId、版本与当前状态 |
| 生成或修订计划 | POST /api/evaluation-tasks/{id}/plans | 受理规划，随后查询对应版本 |
| 审批计划 | POST /api/evaluation-tasks/{id}/approvals | 关联待审批版本，保存意见与授权 |
| 启动运行 | POST /api/evaluation-tasks/{id}/runs | 返回 runId；不等待整次评测完成 |
| 查看运行 | GET /api/evaluation-runs/{runId} | 真实状态、预算、覆盖和复核摘要 |
| 暂停 / 恢复 / 停止 | POST /api/evaluation-runs/{runId}/commands | 校验 expectedVersion 与允许状态后受理命令 |
| 获取运行事件 | GET /api/evaluation-runs/{runId}/events | SSE，支持事件游标恢复 |
| 查看会话 | GET /api/attack-sessions/{sessionId} | 分页读取探测、分支和证据引用 |
| 查看发现 | GET /api/findings/{findingId} | 确认、整改、复现和用例关联 |
| 复核 / 复现 | POST /api/findings/{findingId}/reviews 或 /replays | 分别受理意见或创建有预算的复现执行 |
| 生成候选用例 | POST /api/findings/{findingId}/case-candidates | 进入候选审核状态，尚未启用 |
| 审核候选用例 | POST /api/case-candidates/{id}/reviews | 通过后生成正式版本，退回保留意见 |
| 发起回归 | POST /api/regression-runs | 固定用例版本和新目标快照，创建标准评测运行 |

修改请求使用 expectedVersion（期望资源版本）防止覆盖他人的变更，关键受理请求使用 idempotencyKey（幂等键）防止重复创建；同键不同请求必须报冲突。租户、操作者和权限由服务端认证获得。

接口错误至少区分：资源或权限错误、能力不支持、版本冲突、授权失效、预算不足、执行结果未知。前端不能将所有异常压成“任务失败”。

事件建议覆盖任务状态、计划形成、审批等待、尝试开始、探测受理、目标结果、判定完成、发现产生、预算变化和报告就绪。

| 事件字段 | 类型 / 必填 | 含义 |
| --- | --- | --- |
| eventId | String / 是 | 唯一事件标识，客户端据此去重 |
| sequence | Long / 是 | 单运行内单调递增序号，用于补发；不代表跨运行全局顺序 |
| runId / taskId | String / 是 | 本次运行及任务 |
| eventType | String / 是 | 带契约版本管理的事件类型 |
| occurredAt | Timestamp / 是 | 事件实际发生时间，界面按用户时区展示 |
| subjectRef | String / 是 | 事件涉及的计划、会话、探测、发现等对象 |
| payloadRef | String / 否 | 较大内容的受权访问引用，不在 SSE 内广播完整敏感数据 |
| schemaVersion | String / 是 | 事件结构版本 |

事件重复或短暂乱序不能触发重复目标调用。客户端先取状态快照，再按游标续订；SSE 断线只影响展示，不改变后台运行。

## 14. 指标、效果评估与报告

### 14.1 三类任务使用不同统计口径

| 场景 | 指标 | 明确口径 |
| --- | --- | --- |
| 标准评测 | 已观测风险率 | RISK_OBSERVED 用例数 /（RISK_OBSERVED + NO_RISK_OBSERVED 用例数）；同时报告总数、无法判断、不适用和错误数 |
| 标准回归 | 复发情况 | 固定用例在新快照下命中 / 未命中 / 不确定 / 执行失败的数量，保留重复运行结果 |
| 自动红队 | 有效发现数 | 去重后经复核确认的风险发现数，不等于命中探测次数 |
| 自动红队 | 尝试命中率 | 满足成功判据的尝试数 / 有明确风险或未观察到风险结论的尝试数；自动判定和复核确认分别统计，列出待定与错误等排除项 |
| 自动红队 | 复现情况 | 每项发现的命中次数 / 实际有效复现次数；未知和错误独立列出 |
| 自动红队 | 探索效率 | 确认发现数 / 实际费用，并同时给出耗时、目标请求和 Agent 请求数 |
| 样本生产 | 质量与采纳 | 质检通过、去重剔除、人工采纳、退回比例，分别给出分母 |
| 共用 | 覆盖情况 | 计划的风险 × 策略组合中，已执行且证据符合要求的组合比例 |
| 共用 | 判定质量 | 在独立人工标注集合上的误报与漏报评估，不用模型自报置信度代替 |

分母为零显示“不适用”，不能显示 0% 安全风险。去掉错误项后的比例必须同时展示原始总数和排除数量，避免掩盖目标不可用或评分失败。

探索任务的输入受反馈影响，不能直接与固定基准风险率横向比较。策略比较至少固定目标快照、风险范围、种子来源、判据和预算，进行多次独立运行并报告波动。

### 14.2 报告内容

报告展示目标与规则版本、授权范围、测试模式、计划与实际覆盖、预算与实际消耗、确认发现、疑似发现、原始证据入口、复现结果、整改与回归状态，以及未覆盖项和局限。

报告数字来自代码统计，描述来自有引用的事实。未完成复核时可以生成阶段报告，必须标明待确认部分；正式发布依据既定审批规则。

导出按权限脱敏。目标响应中的 HTML、Markdown 链接及脚本作为不可信内容展示，不能在报告或界面中被执行。

### D01：锁定契约，打通共享探测执行

当前源码入口、字段、静态单轮与证据边界见[D01源码接入说明](D01-共享探测执行与证据接入说明.md)。这是实现接入补充，不替代以下业务要求或集成验收。

**功能：** 一个授权目标接受一次受控探测，返回可查询的执行记录、证据引用和真实消耗。这是动态攻击的底座验证，不另建样本评测流水线。

**建议新增或扩展：** TargetCapabilityPort、TargetSessionPort、ProbeExecutionPort、AssessmentPort、TargetSnapshot、ProbeCommand、TargetObservation、BudgetPolicy，以及 eval 中的适配实现。复用 EvaluationResourcePort 与已有批量端口。

**开发动作：** 明确动态执行事实放在哪里，识别当前模型调用和判定服务对批次、单样本结果的耦合；仅抽取必要共享能力，不整体重写流水线。

**验收：**

- 同一幂等请求不会创建两个逻辑探测；不支持的目标能力明确报错。
- 输入、响应、错误和账目可追溯；提交超时不会盲目重复目标操作。
- 原有标准评测仍能执行，判定口径没有被动态场景意外改变。
- 接入一个真实允许测试的目标完成链路；测试替身只用于稳定验证机制，不作为攻击效果证据。

### D02：交付反馈驱动的自动红队任务

当前任务、同步反馈循环、预算和动作字段见[D02源码接入说明](D02-反馈驱动自动红队接入说明.md)。首版使用规则反馈Agent，运行启动不具请求级幂等键，D03控制命令不适用于D02；源码交付不等于以下验收已通过。

**功能：** 创建任务、使用一个固定策略，在预算内依据目标响应调整下一次输入，输出停止原因和疑似发现。

**建议类：** EvaluationTaskService、EvaluationOrchestrator、AdaptiveAttackAgent、AttackSessionRunner、AttackAction、ActionValidator、BudgetLedger、AgentRunRecorder。

**范围：** 先用一项明确风险和预设计划模板，完成自适应单轮搜索。无需先完成通用规划 Agent、经验检索或所有风险分类。

**验收：**

- 不同目标回复能影响后续动作，而非把预先生成的一批样本依次发送。
- 每次单轮探测使用干净目标上下文，攻击者可读取本次任务历史。
- 调用上限、停止、重复输入限制和无进展条件由代码生效。
- 前端已有创建、运行状态、尝试轨迹和结果入口。

### D03：交付多轮会话与运行恢复

2026-10-01 coding 状态：第一版线性多轮、消息重放、检查点/操作日志、租约Worker、控制命令和SSE补发源码已加入，接入边界见[D03源码接入说明](D03-多轮会话与运行恢复接入说明.md)。未执行迁移、编译、测试或真实目标请求，本节验收尚未通过；重置/分支、正式Judge、完整授权及未知结果自动核对不在已完成范围内。

**功能：** 在同一目标会话内推进攻击，支持暂停、恢复、停止和断线重连。

**建议类：** AttackSession、SessionCheckpoint、TaskCommandService、RunEventService、SessionAssessmentRouter，以及 TargetSessionPort 实现扩展。

**验收：**

- 至少一个场景依赖早前会话内容才能形成后续观察；不能以多次独立调用冒充多轮。
- 同一会话串行，不同会话按预算并行；重启后恢复到真实检查点。
- 早期拒答不自动结束整段会话；会话结果引用完整轨迹。
- 结果未知、目标会话过期和停止后迟到响应均有可解释状态。
- 目标不支持重置或分支时不展示相应能力；首批可以只交付线性多轮。

### D04：交付发现、复现和固定用例回归

**功能：** 疑似发现归并，证据复核，独立复现，生成候选用例并审核，对新版本执行固定用例回归。

**建议类：** FindingService、FindingVerifier、ReplayService、RegressionCaseService、FindingReview、ReproductionRecord、RegressionRunReference。

**验收：**

- 原判定、复核意见、人工结论和复现结果分别保存。
- 多轮用例保留前置条件、完整步骤和断言。
- 同一问题在修复前后运行有明确对比，回归失败能重新打开问题。
- 调用失败与证据不足不被计作修复成功；复现费用计入任务或单独批准的验证预算。

### D05：交付独立样本工厂与定时生产

**功能：** 专家配置种子，定时生成、去重、质检，次日审核启用。

**建议类：** SampleProductionService、SampleGenerationWorkflow、SampleQualityWorkflow、CandidateCaseService、AssetReviewService、ScheduledTaskTrigger。

**验收：**

- 工厂任务本身不调用被测目标，不产生目标安全结论。
- 种子、父样本、变异链、生成配置、质检和人工意见可追溯。
- 同一计划时间的重复触发不会产生重复批次；时区、漏触发和补跑策略明确。
- 审核通过才启用正式资产，能够被标准评测选中。

### D06：交付跨策略规划、报告与受控经验

**功能：** 根据目标和覆盖安排策略，分析已计算指标，生成有引用的报告，审核后复用经验。

**建议类：** EvaluationPlannerAgent 的实现、StrategyRegistry、EvaluationAnalysisWorkflow、ReportComposer、ExperienceCurationWorkflow、ExperienceRetriever。

**验收：**

- 规划只能选择目标支持且已授权的策略，不修改执行事实。
- 报告区分确认与疑似发现，数字与底层统计一致。
- 新版本经验能追溯来源与审核；盲测不能检索隐藏测试答案。
- 规划或报告模型不可用时，保留原始结果并提供可用的结构化摘要。

### D07：扩展应用级风险与研发持续回归

**功能：** 按能力逐项增加 RAG、工具型应用、间接注入场景和 CI 触发。

**建议扩展：** 场景夹具与清理服务、工具证据适配、身份隔离适配、ScenarioAssessment、回归 API 和稳定的机器可读结果。

**验收：**

- 针对权限与工具风险提供实际行为证据，不能只依据模型声称。
- 每个新策略声明支持的目标能力、风险判据和清理要求。
- CI 可选择固定回归集和明确阻断条件，遇到不确定或基础设施错误有单独处理策略。
- 外部框架如被引入，仍服从本平台的预算、状态与证据规则。

D01～D04 是自动红队的首条核心交付链。D05 可在契约稳定后并行推进，但不能以生成和报表页面代替动态攻击闭环的完成。

同时保留现有标准评测接入，记录多轮会话、场景证据和预算计量尚不支持的能力。随后进入 D02 的真实反馈循环。产品方案不要求此时重写所有 Agent、升级 Spring AI 或拆微服务。

## 18. 决策记录、待核实事项与资料

### 18.1 已作出的设计取舍

| 取舍 | 理由 |
| --- | --- |
| 三类任务统一工作台 | 用户目标不同，结果和统计口径需要清晰；共用权限、资产和证据 |
| 风险发现连接回归 | 单次命中只有经过证据验证和后续修复检查，才能形成持续价值 |
| 动态输入与正式资产分开 | 支持实时反馈决策，同时维持资产准入质量 |
| 规划与攻击两层循环 | 区分任务级覆盖决策与会话级即时决策，控制成本和复杂度 |
| 共享执行底座、不同执行模式 | 复用现有能力，并支持当前批量数据模型无法直接表达的会话 |
| 运行、复核、整改各自有状态 | 执行完成不代表风险已确认或问题已修复 |
| 继续 Spring AI 与模块化工程 | 当前产品问题不需要以切框架、改部署作为前置条件 |

### 18.2 开发前需要核实的工程事实

这些事项由 coding 分支通过代码和接入验证确认，不妨碍按本方案开始 D01：

- 现有目标适配能否提供完整消息历史、目标会话标识及请求状态查询。
- 单样本结果与判定组件的具体耦合点，哪些可以抽为共享服务。
- 现有账号、租户和凭据管理如何映射运行授权及测试身份。
- 当前数据库与事件设施支持哪些持久化、事务和幂等机制。
- 所选目标及模型服务能提供哪些真实用量、定价和版本信息。

暂不支持的能力要在目标登记和前端禁用项中明确反映，不能依靠提示词承诺实现。
