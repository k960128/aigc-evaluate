# 模型安全评测智能体 · 0 到 1 开发路线

> 版本：v0.1  
> 适用模块：`eval-agent`  
> 目标读者：Java 开发者、安全专家、技术负责人  
> 产品定位：面向大模型上线前安全验证的可扩展、可追溯、可复现评测平台

## 1. 文档目标

本文档回答四个问题：

1. 当前仓库已经有什么，缺什么；
2. 从 0 到 1 应该按什么顺序开发；
3. 开发者和安全专家分别负责什么；
4. 每个阶段做到什么程度才可以进入下一阶段。

本文档采用“架构路线”深度，描述模块边界、实现顺序、依赖关系、风险和验收标准，不展开每个类的完整代码教程。

## 2. 项目定位

模型安全评测智能体的目标，是把安全专家定义的风险规则和测试样本，转化为一条稳定的自动化评测流程：

```text
评测目标与预算
  → 攻击计划
  → 攻击样本
  → 目标模型响应
  → 安全判定
  → 复核与证据
  → 结果统计与经验沉淀
```

平台本身不承诺替代安全专家创造高级攻击方法。首版优先使用公开安全基准集和配置化样本，由安全专家负责规则、样本和结果审核，由开发者负责调度、执行、约束、存储和观测。

### 2.1 技术竞争力

项目的技术竞争力来自评测工程化能力：

- 用确定性 Java 编排器控制预算、状态机、并发、重试、幂等和停止条件；
- 用业务契约隔离智能体实现与 Spring AI、AgentScope 等运行时；
- 用模型网关适配不同厂商、不同模型角色和 Mock 测试替身；
- 用追加式事实、版本快照和事件链保证结果可追溯、可复现；
- 把安全专家的规则和样本做成可插拔输入，形成持续积累的评测资产。

## 3. 当前仓库状态

### 3.1 `eval-agent` 当前已有内容

当前模块是 Maven 子模块，使用 Java 21 和 Spring Boot 3.5.x，依赖 `framework`、`infra-ai` 和 Spring Web。

现有代码主要用于技术验证：

- `AgentController`：只有 `GET /eval-agent/chat`，返回 `hello world`；
- `SimpleReactAgent`：天气和搜索工具的 ReAct 示例；
- `PlanExecuteAgent`：空壳示例；
- `SparkChatClient`：单点客户端示例；
- 示例工具和配置类。

当前没有以下业务实现：

- `Campaign`、`Task`、`Round` 等业务契约；
- `RedTeamOrchestrator` 或其他确定性编排器；
- `TargetModelGateway`、`SampleAgent`、`JudgeAgent`；
- 任务、样本、响应、判定和事件持久化；
- SSE 事件流、任务检查点和恢复机制；
- `eval-agent` 自己的测试目录。

`eval-agent` 没有独立启动类，首版继续作为 `eval` 应用内模块运行，由 `LLMEvalApplication` 通过 `com.kant.agent` 包扫描加载。

### 3.2 可复用的现有底座

`infra-ai` 已有以下真实入口：

- `ModelClientStrategyFactory`：根据 `ClientModelInfo` 获取模型调用策略；
- `ModelClientStrategy#call(ModelRequest)`：调用目标模型；
- `JudgeModelClient#judge(JudgeModelRequest)`：调用 Judge 模型；
- Embedding、Rerank 相关服务：供后续知识和经验检索使用；
- Mock 模型策略：供本地测试和压测使用。

`framework` 已有以下通用能力：

- 统一 `Result` / `Results` 响应；
- Redis、RocketMQ、分布式 ID 和幂等基础设施；
- SSE 发送工具；
- 统一异常和 Web 配置。

现有 `ModelClientService` 当前为空实现，不能直接作为目标模型网关使用。首版应封装 `ModelClientStrategyFactory`，或补充一个真正的 facade。

### 3.3 与现有稳定评测流水线的关系

`eval` 已有稳定的模型调用和安全评测流水线，负责批量调用、L1/L2/L3 判定和节点日志。`eval-agent` 的职责是生成和组织主动评测样本。

两者通过业务契约连接：

```text
eval-agent
  → 样本批次 / 目标模型 / 规则版本
  → eval 稳定评测流水线
  → 响应 / 风险结论 / 节点证据
  → eval-agent 反馈与统计
```

首版可以使用 `TargetModelGateway` 完成小规模单样本闭环，但接口语义应与正式流水线保持一致，避免形成两套互不兼容的调用和判定口径。

## 4. 开发边界与职责分工

### 4.1 首版明确不做

- 不自动修改目标模型参数或训练模型；
- 不让智能体修改风险规则；
- 不让智能体直接访问数据库、MQ 或任意网络资源；
- 不实现无约束的多智能体自然语言互聊；
- 不要求开发者独立构造高级攻击技术；
- 不在第一版引入完整自适应多轮攻击和长期经验检索。

### 4.2 开发者负责

- 业务契约和模块分层；
- 任务状态机和确定性编排；
- 目标模型和 Judge 模型适配；
- 预算、并发、超时、重试、限流和幂等；
- 任务、样本、响应、判定、事件的保存与恢复；
- REST、SSE、日志、指标和测试；
- 配置管理、密钥外置和部署。

### 4.3 安全专家负责

- 风险分类、风险规则和判定口径；
- 公开基准集和种子样本筛选；
- 样本质量审核和高风险结果确认；
- Judge / Verifier 结果抽检；
- 经验记录是否进入默认检索集合。

首版使用公开基准集。安全专家主要参与规则校验、样本审核和结果抽检，不要求开发者承担安全研究职责。

## 5. 总体架构

```text
前端 / API
    ↓
Application Service
    ↓
RedTeamOrchestrator（确定性 Java）
    ├── SupervisorAgent（后续阶段）
    ├── StrategyAgent（后续阶段）
    ├── SampleAgent
    ├── TargetModelGateway
    ├── JudgeAgent
    ├── VerifierAgent（后续阶段）
    ├── EventPublisher
    └── Persistence / Checkpoint
             ↓
      framework / infra-ai / eval 流水线
```

推荐包结构：

```text
com.kant.agent
├── controller       # REST、SSE、任务控制
├── application      # 用例服务和事务边界
├── orchestration    # 状态机、预算、重试、幂等
├── contract         # 与框架无关的业务对象
├── agent            # Supervisor、Strategy、Sample、Judge、Verifier
├── gateway          # TargetModelGateway 等业务能力适配
├── persistence      # Mapper、Repository、事实保存
├── event            # AgentEvent、事件发布和订阅
└── config           # 模型、线程池、预算和运行配置
```

依赖方向固定为：

```text
controller → application → orchestration → contract
agent / gateway → infra-ai
persistence / event → framework
```

`contract` 和 `orchestration` 不暴露 Spring AI 的 `ChatClient`、`Message`、Prompt 等类型。

## 6. 统一业务契约

契约对象是第一项开发内容。它们应使用普通 Java 类型，并至少携带以下追踪字段：

```text
campaignId
taskId
roundId
traceId
agentRunId
modelVersion
ruleVersion
schemaVersion
```

首版需要定义：

| 对象 | 用途 |
|---|---|
| `AgentContext` | 一次智能体执行所需的裁剪后上下文 |
| `AgentEvent` | 前端展示、审计和回放事件 |
| `AgentJob` | 编排器分发给智能体的结构化任务 |
| `StrategyCard` | 风险类别、攻击技术、目标和尝试约束 |
| `AttackSample` | 样本文本、来源、变异信息和指纹 |
| `TargetResponse` | 目标模型响应、调用状态和耗时 |
| `JudgeVerdict` | 风险结论、严重度、置信度和证据 |
| `VerificationVerdict` | 独立复核结论及与原判定的关系 |

建议预留以下生命周期对象：

```text
RedTeamCampaign
RedTeamTask
RedTeamRound
AgentRun
ExperienceRecord
```

原始样本、目标响应和判定记录采用追加式保存。复核和经验摘要生成新记录，并通过来源 ID 关联原始事实，禁止覆盖历史判定。

## 7. 分阶段开发路线

### M0：工程准备与契约定义

#### 目标

建立可供后续模块依赖的业务协议和安全的工程基础。

#### 开发任务

1. 确认 `eval-agent` 继续由 `eval` 应用启动和扫描；
2. 清理示例代码中的硬编码 API Key，统一改为配置文件或环境变量；
3. 建立 `contract` 包和基础枚举；
4. 定义任务、轮次、智能体运行、样本、调用、判定和事件的关联字段；
5. 定义任务状态、样本状态、调用状态、判定状态和错误类型；
6. 定义 `AgentExecutor<I, O>` 等业务接口，但不绑定具体 AI 框架；
7. 增加基础序列化和校验规则。

#### 依赖

无业务模块依赖，可直接基于 Java 21 和现有 framework 编写。

#### 阶段出口

- 契约可以独立编译和序列化；
- 业务对象不依赖 Spring AI；
- 所有后续结果都能关联到任务、轮次、模型和规则版本；
- 密钥不再写入 Java 源码。

### M1：单轮最小闭环

#### 目标

先完成一条能运行、能保存、能解释的最小链路：

```text
创建任务
  → 配置化或公开基准样本
  → TargetModelGateway
  → JudgeAgent
  → 保存结构化结果
```

#### 开发任务

1. 实现 `TargetModelGateway`，内部调用 `ModelClientStrategyFactory`；
2. 统一目标模型请求、响应、超时、有限重试和失败状态；
3. 保存本次模型配置快照、调用耗时、Token 和重试次数；
4. 实现首版 `SampleAgent`，优先读取公开基准集或配置化样本；
5. 实现 `JudgeAgent`，封装 `JudgeModelClient`；
6. 对 Judge 原始输出执行 JSON 解析、字段校验和有限结构化重试；
7. 实现 `RedTeamOrchestrator` 的单轮状态流转；
8. 增加预算检查、样本指纹去重和幂等键；
9. 使用 Mock 模型完成本地闭环验证。

#### 首版状态流转

```text
CREATED → VALIDATING → RUNNING → JUDGING → COMPLETED
                                      ↓
                                    FAILED
```

#### 阶段出口

- 一次任务可以从创建运行到生成 `JudgeVerdict`；
- Judge 结果包含 `RISK / SAFE / UNCERTAIN`、严重度、置信度和证据；
- 目标模型超时、调用失败和 Judge 解析失败不会导致进程崩溃；
- 重复样本不会重复执行；
- Mock 模型下可以完成自动化测试。

### M2：任务管理与运行事件

#### 目标

把单轮闭环变成可操作、可观察、可恢复的后端任务。

#### 开发任务

1. 增加创建、查询、启动、暂停、恢复和终止接口；
2. 增加 SSE 事件流，输出任务阶段、样本、响应摘要、判定和异常；
3. 增加任务、轮次、样本、响应、判定和事件的持久化；
4. 将运行态和检查点保存到 Redis 或其他现有运行态存储；
5. 将关键事实保存到 MySQL；
6. 增加服务重启后的未完成任务恢复；
7. 首版使用线程池或应用内异步执行，暂不强制引入 MQ；
8. 为后续 RocketMQ 执行方式保留任务消息和幂等字段。

#### 推荐接口

```text
POST /eval-agent/tasks
GET  /eval-agent/tasks/{taskId}
POST /eval-agent/tasks/{taskId}/start
POST /eval-agent/tasks/{taskId}/pause
POST /eval-agent/tasks/{taskId}/resume
POST /eval-agent/tasks/{taskId}/cancel
GET  /eval-agent/tasks/{taskId}/events
```

#### 阶段出口

- 前端可以查看任务状态和事件流；
- 重复启动、重复恢复和重复消息不会创建重复事实；
- 服务重启后可以从检查点继续；
- 暂停和终止不会破坏已保存的样本级结果。

### M3：策略智能体与有限多轮

#### 目标

在单轮链路稳定后，再让模型参与策略选择和下一轮规划。

#### 开发任务

1. 实现 `StrategyAgent`，根据风险范围、公开知识和历史摘要生成 `StrategyCard`；
2. 实现受约束的 `SupervisorAgent`；
3. 编排器校验 Supervisor 输出的风险范围、样本数、调用数和工具权限；
4. 增加有限轮次循环；
5. 增加风险覆盖率、连续无新增、预算耗尽和高风险阈值停止条件；
6. 记录每轮计划、实际执行结果和停止原因；
7. 接入公开安全基准集和基础风险规则。

#### 阶段出口

- 系统能在预算约束下执行多轮评测；
- 非法计划会被编排器拒绝或有限重试；
- Supervisor 只能提出继续或停止建议，不能绕过 Java 约束；
- 可以按风险类别统计覆盖率。

### M4：复核、经验与扩展能力

#### 目标

让评测结果具备独立复核、人工审核和持续沉淀能力。

#### 开发任务

1. 实现 `VerifierAgent`，对高风险、低置信度和规则冲突结果独立复核；
2. 增加人工复核状态、意见和操作记录；
3. 增加 `ExperienceRecord`，保留样本、响应、判定和复核来源；
4. 只有审核通过的经验进入默认检索集合；
5. 接入 Embedding、Rerank 和 PGVector；
6. 增加自适应多轮攻击；
7. 通过稳定业务契约对接 `eval` 现有评测流水线。

#### 阶段出口

- 原始 Judge 判定不会被复核覆盖；
- 每条经验都能追溯到原始样本和证据；
- 经验检索不会污染盲测数据集；
- 自适应攻击具有最大轮次、响应长度和调用预算限制。

## 8. 关键接口边界

### 8.1 智能体执行接口

业务层只定义输入、输出和事件，不暴露具体模型框架：

```java
public interface AgentExecutor<I, O> {

    Mono<O> execute(I input, AgentContext context);

    Flux<AgentEvent> stream(I input, AgentContext context);
}
```

具体实现可以在 `agent` 包内部使用 Spring AI，但 `contract` 和 `orchestration` 不得引用 Spring AI 类型。

### 8.2 目标模型网关

`TargetModelGateway` 负责：

- 根据模型配置选择 `ModelClientStrategy`；
- 统一输入和输出格式；
- 处理超时、限流、重试和失败分类；
- 记录模型版本、参数快照、Token、耗时和请求状态；
- 为 Mock、真实模型和现有评测流水线提供一致的业务语义。

### 8.3 Judge 边界

`JudgeAgent` 只接收判定所需的攻击样本、目标响应、风险规则和规则版本，不继承攻击智能体的主观结论。

Judge 输出至少包括：

```text
verdict: RISK | SAFE | UNCERTAIN
riskCategory
severity
confidence
evidence
ruleReferences
needsVerification
```

## 9. 数据与事件原则

### 9.1 事实保存

以下内容必须支持追加式保存和回放：

- 原始攻击样本；
- 目标模型原始响应；
- Judge 原始输出和结构化结果；
- Verifier 复核结果；
- 模型和规则配置快照；
- 智能体运行事件和异常。

复核、重判和经验摘要生成新记录，并通过来源字段关联历史事实。

### 9.2 事件字段

每条事件至少包含：

```json
{
  "eventId": "evt_xxx",
  "taskId": "task_xxx",
  "roundId": "round_xxx",
  "agentRunId": "run_xxx",
  "type": "ATTACK_SAMPLE_CREATED",
  "status": "RUNNING",
  "payload": {},
  "occurredAt": "2026-09-13T10:00:00+08:00"
}
```

事件面向前端展示、监控和审计回放。智能体完整思考过程不作为产品事实，前端只展示可解释的动作摘要。

## 10. 失败处理与停止条件

### 10.1 失败分类

| 失败类型 | 处理方式 |
|---|---|
| 参数或结构错误 | 记录错误，有限重试，仍失败则任务失败 |
| 样本重复 | 丢弃重复样本，要求生成新变体或跳过 |
| 目标模型超时 | 按模型策略重试，超过阈值记录调用失败 |
| 目标模型限流 | 延迟重试并遵守并发和速率限制 |
| Judge 无法解析 | 结构化重试，仍失败则转不确定或人工复核 |
| 重复消息 | 通过任务阶段、幂等键和样本指纹拦截 |
| 服务重启 | 从持久化检查点恢复 |
| 经验写入失败 | 不影响原始评测结果，进入补偿队列 |

### 10.2 编排器控制的停止条件

Supervisor 只能提出停止建议，最终由编排器判断：

- 已覆盖所有目标风险类别；
- 达到最大轮次；
- 达到最大样本数或模型调用预算；
- 连续多轮没有新增覆盖或有效信息；
- 已发现达到阈值的高风险结果；
- 用户暂停或终止；
- 目标模型不可用且超过重试上限。

## 11. 测试与验收

### 11.1 M0 验收

- 契约对象可以编译、序列化和反序列化；
- 状态、错误和追踪字段定义完整；
- 业务对象不依赖 Spring AI；
- 密钥不再硬编码在源代码中。

### 11.2 M1 验收

- Mock 模型下可以完成单轮闭环；
- 目标模型超时、限流和失败状态可控；
- Judge 输出可以解析成结构化 `JudgeVerdict`；
- Judge 解析失败可重试或转人工路径；
- 重复样本不会重复调用目标模型；
- 结果能追溯到任务、样本、响应、规则和模型配置。

### 11.3 M2 验收

- REST 接口可以创建、启动、查询、暂停、恢复和终止任务；
- SSE 可以看到阶段进度和关键事件；
- 重复启动、重复恢复和重复消息不会重复执行；
- 服务重启后可以恢复未完成任务；
- 已保存事实不会因暂停或终止丢失。

### 11.4 M3 验收

- 预算耗尽后任务一定停止；
- 非法 Supervisor 计划不能越过风险范围和预算约束；
- 覆盖完成、连续无新增和用户终止都能正确停止；
- 可以按风险类别和攻击技术统计覆盖率。

### 11.5 M4 验收

- 高风险和低置信度结果可以进入 Verifier；
- 复核记录保留原始 Judge 判定；
- 人工审核意见和操作人可追溯；
- 经验记录可回溯到样本、响应和复核证据；
- 盲测任务不会直接读取包含答案的经验集合。

### 11.6 基础验证命令

```text
mvn -pl eval-agent -am test
```

首版测试重点是 Mock 模型、契约序列化、编排器状态迁移、预算、幂等、去重、Judge 解析失败和任务恢复。真实外部模型压测放到后续阶段，避免产生不必要的调用成本和限流影响。

## 12. 推荐实施顺序

按以下顺序提交和验收，避免一开始同时建设所有智能体：

1. 工程准备、密钥外置和业务契约；
2. 目标模型网关与 Mock 适配；
3. JudgeAgent 和结构化判定；
4. 单轮 RedTeamOrchestrator；
5. 事实持久化、预算、幂等和去重；
6. REST、SSE 和任务恢复；
7. StrategyAgent、SupervisorAgent 和有限多轮；
8. Verifier、人工复核和经验审核；
9. Embedding、Rerank、自适应攻击和稳定流水线对接。

每完成一个阶段，先用 Mock 和固定公开样本验证阶段出口，再接入真实模型或更复杂的安全策略。

## 13. 最终判断标准

项目从 0 到 1 完成的标准，不是“生成了多少攻击 Prompt”，而是：

- 安全专家提供的规则和样本可以被稳定执行；
- 每个风险结论都有完整证据链；
- 相同配置可以复现相同评测过程；
- 预算、并发、重试、幂等和停止条件由代码强制生效；
- 服务异常或重启后不会重复执行或丢失事实；
- 新模型、新规则和新策略可以通过接口和配置接入；
- 评测结果可以被现有稳定流水线消费或复用。

这就是开发者能够直接证明的技术价值：把安全专家的知识工程化，形成可扩展、可审计、可持续演进的模型安全评测基础设施。
