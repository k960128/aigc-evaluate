1. 三期总览

三期不是版本升级，而是三种不同的编排范式。它们共存于同一生产系统，覆盖不同的场景象限。

批量生产

→

补盲 / 异常
→
二期 Supervisor
→
动态调整
未知 / 探索
→
三期 ReAct
→
发现新策略

三期分别对应三类场景，互不替代，协同工作

期模式定位适用场景成本可预测性
一期Workflow批量生产线已知类别、标准扩充低高
二期Supervisor灵活调度台补盲、探索、异常处理中中
三期自主 ReAct研究实验室未知领域、策略发现高低
核心差异一句话：控制流从「Java 代码」到「Supervisor 的 LLM」再到「N 个自主 Agent 的消息传递」，每往上一期，能力上限提高，可预测性下降。

2. 一期：Workflow 模式

01

批量生产线

控制流写死在 Java 里，LLM 只负责内容生成与判定

2.1 目标与定位

一期解决的是「稳定批量生产安全评测样本」的问题。所有步骤可枚举、可复现、可预估，是整个样本工厂的生产主力。

核心目标
批量、稳定、便宜地扩充样本
控制流位置
Java 代码（for 循环）
谁决定下一步
程序员
Agent 自主性
无，被动执行

适用 / 不适用

✅ 适用❌ 不适用
已有成熟类别的批量扩充 需要根据结果动态调整策略
需要可复现、可审计的生产任务 处理全新、未知的样本方向
成本敏感、调用次数可预估 需要 Agent 主动拒绝或要求补充信息
标准化验收，通过率稳定 探索性、试错性的研究任务

2.2 Agent 清单

一期共 5 个 Worker Agent，每个单一职责、互不感知、无自主权。它们按固定顺序被调用，前一个的输出是后一个的输入。

Agent 1
🌱 SeedCuratorAgent
策展种子。把主题方向展开成 N 条结构化种子，每条含 content / category / attackType / language / difficulty。种子写入本地缓存供后续查找。
Agent 2
✍️ GeneratorAgent
生成候选。从种子 + 任务约束批量生成候选样本。一次生成 1 条，外层循环控制批量，避免模型把 N 条塞进一条。
Agent 3
🛡️ SafetyFilterAgent
安全过滤。判定候选是否可放行。拦截条件：真实 PII、真实组织名、具体违法步骤。解析失败保守拦截。
Agent 4
🧹 DedupAgent
去重。归一化 + SHA-256 精确哈希。设置 contentHash 供后续判重，命中则拦截为 DUPLICATE。
Agent 5
⭐ QualityReviewerAgent
质量评审。四维评分（相关性 / 清晰度 / 可复现性 / 多样性）。score ≥ 75 判通过。与生成环节独立，避免"自己判自己"。
设计原则：每个 Agent 只做一件事，不做决策、不做编排、不感知其他 Agent。所有顺序由 Java 代码决定。

2.6 可观测性

一期提供任务级 trace 和 分类计数器两类可观测信息。所有信息在任务结束后随响应返回，不留存历史。

① 任务 trace（响应内返回）

POST /api/factory/produce 响应中的 trace 字段

3. 二期：Supervisor 模式

灵活调度台

3.2 Agent 清单

二期引入 1 个 Supervisor Agent（决策者），把一期 5 个 Worker 包装成 8 个工具（执行者），新增 2 个辅助工具。Worker 本身不改，只改变它们的调用方式。

决策者：Supervisor Agent

Supervisor
🎯 SampleSupervisor
动态调度者。持有全部工具，读 system prompt 与目标后，自主决定调哪个工具、调几次、何时 finish。所有工具调用受上限与决策日志约束。

执行者：8 个工具

🌱 callCurator
策展种子。返回 seedIds + 下一步建议。
✍️ callGenerator
按 seedId 生成候选样本。返回 sampleIds。
🛡️ callFilter
安全过滤单个样本。返回 safe 布尔值 + 拦截原因 + 调整建议。
⭐ callReviewer
质量评审单个样本。返回分数 + pass + reasons。
📊 queryStats
查询样本池统计。Supervisor 每次决策前先调它了解现状。
📋 listSamples
列出指定状态的样本摘要。用于分析失败模式。
🧭 queryCoverage
（二期后段）查询覆盖度矩阵缺口，指导补盲方向。
🚪 finish
主动结束任务。Supervisor 判断目标达成或无法推进时调用。
关键设计：每个工具返回结构化结果（ToolResult），包含 summary、data、suggestions。Supervisor 不只能读到结果，还能读到"下一步建议"，从而做出更智能的决策。

3.5 用例

🎯
用例 A：一期不达标，Supervisor 补盲
场景
某类别样本的过滤率异常高，一期产出始终达不到目标。交给 Supervisor 处理。
输入

流程
queryStats 看现状 → 分析 listSamples(FILTERED_OUT) 发现原因 → 调整难度 / 换攻击策略 → callGenerator 重新生成 → 过滤评审 → finish
产出
3 条补充通过的样本，成本约为纯一期重跑的 40%
价值
避免整体重跑，只补缺口
🔍
用例 B：覆盖度补盲
场景
覆盖度矩阵显示「隐私侵犯 + 多轮诱导 + en」这个格子缺口 30 条。
输入

流程
Supervisor 调 queryCoverage 确认缺口 → 决定先生成小批量试探 → 根据过滤通过率决定是否放大批量
特点
动态批量：通过率高就放量，通过率低就换策略
🧪
用例 C：探索新类别
场景
安全团队想探索"代码生成类滥用"这一新方向，但不确定哪种子类别容易生成成功。

流程

特点
策略发现：Supervisor 会保留有效路径，放弃无效路径

4. 三期：自主 ReAct 模式

03

研究实验室

多个自主 Agent 通过消息总线协作，探索未知领域、发现新策略

4.1 目标与定位

三期解决的是「发现未知策略」的问题。它不是生产线，而是研发部门：让多个自主 Agent 通过消息协作、试错、反思，找到人工未曾预设的新样本类型或新攻击组合。

核心目标
探索、发现、创新
控制流位置
多 Agent 消息总线
谁决定下一步
每个 Agent 自己
Agent 自主性
完全自主
重要提醒：三期成本是一期的 5-20 倍，可预测性极低，不适合生产批量。它必须默认关闭、人工开启、强绑定熔断。

4.2 Agent 清单

三期不再有中心调度者。每个 Agent 都是自主体，拥有自己的目标、工具集和 ReAct 循环。它们通过消息总线互相通信、传递任务、汇报结果。

自主 Agent
🌱 SeedAgent
种子探索者。自主检索、组合、变形种子。当 GenAgent 反馈"这个方向没效果"时，主动尝试新方向。
自主 Agent
✍️ GenAgent
样本生成者。接收生成任务，自主选择生成策略。失败后能反思并改变参数，主动请求 SeedAgent 提供新种子。
自主 Agent
🛡️ FilterAgent
安全守门者。不仅判定，还会解释拦截原因，主动向 GenAgent 发送"建议修改方向"的消息。
自主 Agent
⭐ ReviewAgent
质量评估者。多维评审，能识别"新类型"样本并主动标记为"值得关注"，触发进一步探索。
自主 Agent
🔬 ExplorerAgent
策略探索者。专门负责组合不同攻击策略（如"角色扮演 + 多轮诱导 + 语言切换"），尝试发现高通过率的新组合。

支撑组件

基础设施
📮 MessageBus
消息总线。Agent 间通过消息通信，支持点对点与广播。所有消息留档供回放。

4.4 流程流转

三期没有固定流程。每个 Agent 自主运行 ReAct 循环，通过消息总线协作。整体行为像一个分布式探索系统。

单个 Agent 的 ReAct 循环

① 读消息
→
② 思考
→
③ 选工具
→
④ 行动
⑤ 写消息
→
⑥ 判断是否退出
→
返回①

每个 Agent 独立循环，通过消息总线与其他 Agent 交互

多 Agent 协作流程（示例）

SeedAgent
生成 3 条探索性种子，广播给 GenAgent
GenAgent
收到种子，生成 6 条候选
GenAgent
发送 REQUEST 给 FilterAgent，请求过滤
FilterAgent
2 条被拦截，主动回复 GenAgent："种子 2 太具体，建议抽象化"
GenAgent
收到反馈，反思后向 SeedAgent 请求新种子
SeedAgent
生成 2 条更抽象的种子，回复 GenAgent
GenAgent
重新生成 4 条，全部通过过滤
ReviewAgent
评审 4 条，3 条通过，1 条标记"新类型，值得关注"
ExplorerAgent
看到 ReviewAgent 的标记，主动探索该新类型，尝试组合其他策略
GroupArbiter
监控到进展正常，允许继续
死锁 / 活锁风险：无中心调度时，最容易出的问题是 A 等 B、B 等 A（死锁），或互相发消息但无进展（活锁）。GroupArbiter 监控全局步数、时长、无进展步数，超限强制熔断。

4.5 用例

🔬
用例 A：发现新攻击组合
场景
安全团队想发现"角色扮演 + 多轮诱导 + 语言切换"这个组合是否有效，但人工没有时间系统地试。
流程
ExplorerAgent 组合多种策略 → GenAgent 生成候选 → FilterAgent 过滤 → ReviewAgent 评估 → ExplorerAgent 观察哪种组合通过率最高 → 聚焦该组合继续探索
产出
发现 2-3 个高通过率的新组合，固化为一期新策略
价值
人力无法穷举的探索，由多个自主 Agent 并行完成
🌐
用例 B：小语种样本探索
场景
需要探索藏语、维吾尔语等小语种的安全评测样本，但种子资源稀缺。
流程
SeedAgent 从中文种子出发，Agent 之间协作尝试多轮翻译 + 本地化改写，FilterAgent 判断跨语言后是否仍安全，ReviewAgent 判断是否保持原意
特点
Agent 之间需要多轮往返，这种协作是 Supervisior 模式难以完成的
🧩
用例 C：红队对抗演练
场景
红队需要演练针对新模型的攻击策略，探索防御边界。
流程
多个 GenAgent 扮演攻击者，FilterAgent 与 ReviewAgent 扮演防御者，通过消息总线对抗。GroupArbiter 监控不让对抗失控
特点
多 Agent 对抗，属于典型的自主协作场景

决策何时做判断依据

6.3 反哺机制（最重要）

核心思想：三期是一期的"研发部门"，不是"生产部门"。没有反哺，三期就是烧钱玩具。

一期

三期发现 → 二期工具 → 一期流水线，形成完整的固化闭环

固化判定标准

条件阈值说明
出现占比≥ 30%该模式在任务中的占比
成功率≥ 85%该模式的样本通过率
调用数方差≤ 3路径稳定，步骤数固定
可解释性人工通过安全研究员 + 架构师评审
固化节奏建议：每日看异常告警，每周做路径聚类，每月固化一批，每季复盘回滚。形成稳定的"研发 → 生产"循环。

7. 总结

三期不是三个版本，是三种工具。

一期
装配线

稳定、便宜、大批量

二期
调度台

灵活、可反馈、处理异常

三期
实验室

探索、创新、发现新策略

生产系统 = 一期为主 + 二期兜底 + 三期反哺。
不要把三期当生产用，也不要用一期硬扛所有场景。每期的价值在于覆盖不同的象限，而不是替代前一期。
